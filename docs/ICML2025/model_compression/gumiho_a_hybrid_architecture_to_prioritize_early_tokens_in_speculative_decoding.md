# Gumiho: A Hybrid Architecture to Prioritize Early Tokens in Speculative Decoding

**Conference**: ICML 2025  
**arXiv**: [2503.10135](https://arxiv.org/abs/2503.10135)  
**Code**: [Available](https://github.com/AMD-AIG-AIMA/Gumiho)  
**Area**: Model Compression  
**Keywords**: Speculative Decoding, Hybrid Architecture, Draft Model, Inference Acceleration, Tree Attention

## TL;DR

Proposes Gumiho, a hybrid draft model architecture for speculative decoding: the first two tokens are generated using sequential Transformers to ensure accuracy, while subsequent tokens are generated using parallel MLP heads to improve efficiency. It further increases the accepted length through a Full Tree Attention mechanism, achieving up to 3.65x speedup on Vicuna/LLaMA.

## Background & Motivation

**Background**: Speculative decoding accelerates LLM inference by rapidly generating draft tokens with a small model and verifying them in parallel with a large model. Existing methods fall into two categories: Medusa-style parallel generation (fast but low accuracy because it cannot see unverified tokens in the same step) and Eagle-style sequential generation (accurate but slow).

**Limitations of Prior Work**: Existing methods treat tokens at all positions in the sequence equally, using the exact same model architecture and generation paradigm. However, in practice, once the first incorrect token occurs, all subsequent draft tokens are discarded. Consequently, early-position tokens impact the overall accepted length far more than late-position ones.

**Key Challenge**: Sequential methods (Eagle) offer high accuracy but slow inference; parallel methods (Medusa) offer high speed but low accuracy. A better trade-off between accuracy and efficiency is required.

**Key Insight**: Mathematical proof shows that, while keeping the overall accuracy constant, shifting accuracy from subsequent tokens to early tokens increases the average accepted length $\tau$.

**Core Idea**: Using sequential generation with a larger capacity model (high accuracy) for the first few critical tokens, and lightweight parallel generation (high efficiency) for subsequent tokens — a hybrid architecture.

## Method

### Overall Architecture (pipeline)

1. The LLM outputs the hidden state $h_t$ and token embedding $e(y_t)$, which are concatenated and projected to lower dimensions via a fully connected (FC) layer.
2. **Sequential Phase**: A 2-layer Transformer $\mathcal{M}_T$ autoregressively generates the first 2 draft tokens.
3. **Parallel Phase**: 5 MLP heads $\{\mathcal{M}_M^i\}_{i=1}^5$ take the sequential outputs as input and generate the subsequent 5 tokens in parallel.
4. A total of 7 draft tokens are generated $\rightarrow$ candidates are constructed via an Eagle-2-style dynamic tree $\rightarrow$ verification using Full Tree Attention.

### Key Designs

1. **Serial-Parallel Hybrid Heads**: The first 2 tokens are generated sequentially using a 2-layer Transformer with input $o_t = \text{FC}(\text{cat}(e(y_t), h_t))$. The Transformer captures dependencies between tokens through attention. The subsequent 5 tokens are generated using 5 independent MLPs (2 FC layers + ReLU) sharing the input $\text{cat}(\hat{o}_{t+1}, \hat{o}_{t+2})$.  
**Design Motivation**: Theorem 3.1 proves that improving the accuracy of earlier tokens contributes more to $\tau$ than an equivalent improvement in later tokens; hence, it is worth investing more computation into the initial tokens.

2. **Theorem 3.1 (Early Token Prioritization Theorem)**: Given a draft length $D$ and original acceptance probabilities $\{p_i\}$ (descending), if the probabilities at the first $d$ positions are increased by $\zeta_i$ and the subsequent positions are decreased by the same amount $\zeta_i$ (conserving the sum), then $\mathbb{E}[L]_{\text{improved}} \geq \mathbb{E}[L]_{\text{original}}$.  
**Mechanism**: $\mathbb{E}[L] = \sum_{i=1}^D \prod_{j=1}^i p_j$. Since earlier $p_j$ appear in more product terms, improving the earlier $p_j$ yields larger gains.

3. **Full Tree Attention (FTA)**: The tokens generated by the parallel heads are mutually independent and can be combined arbitrarily. For example, when 3 parallel heads generate $s$ candidates each, there are $s^3$ paths but we only need to compute QKV for $3s$ tokens. FTA allows shorter candidate paths to borrow corresponding-position tokens from longer paths to increase the accepted length.  
**Design Motivation**: The dynamic tree in Eagle-2 might discard subsequent tokens, leading to shorter candidate paths; FTA leverages the independence of parallel heads to complete short paths at zero cost.

### Loss & Training

Following the training method of Eagle-2, the draft model is trained using the hidden states and tokens of the LLM as supervision signals. The sequential Transformer and parallel MLP heads are trained jointly.

| Method | Architecture | Draft Time (Relative) | τ |
|------|------|-----------------|-----|
| Medusa | Fully Parallel MLP | Fastest | Lowest |
| Eagle | Fully Sequential Transformer | Slower | Higher |
| Eagle-2 | Fully Sequential Transformer + dynamic tree | Slower | High |
| Gumiho | Sequential Transformer + Parallel MLP + FTA | Medium | Highest |

### Key Findings

- Gumiho achieves an average speedup of 2.97x across 6 datasets, surpassing Eagle-2's 2.74x (Vicuna-7B).
- On Vicuna 13B, Gumiho reaches a 3.23x speedup, compared to 3.04x for Eagle-2 (a 6.3% gain).
- On LLaMA2-Chat 7B, Gumiho reaches 2.95x, compared to 2.82x for Eagle-2.
- The speedup is most notable on HumanEval: Vicuna 7B Gumiho 3.65x vs Eagle-2 3.27x (τ=5.77 vs 5.35).
- FTA further improves the accepted length, especially on short candidate paths.
- Parallel MLP heads are about 30-40% faster than Transformer heads, with acceptable accuracy loss (since they generate subsequent tokens).
- The advantage of Gumiho is maintained when temperature >0.

## Highlights & Insights

- Mathematical theorem-driven architecture design — first proving that earlier tokens are more important, and then allocating computational resources accordingly.
- The hybrid sequential-parallel concept is simple yet effective, and easy to understand and implement.
- FTA utilizing the independence of parallel heads is a clever "free lunch" — without increasing QKV computation.
- Seamlessly compatible with Eagle-2's dynamic tree, and can be viewed as a direct upgrade to Eagle-2.

## Limitations & Future Work

- The sequential part is fixed to a 2-layer Transformer; the optimal configuration may vary across models/tasks.
- The selection of the sequential-parallel crossover point (first 2 vs. first 3) lacks an adaptive mechanism.
- Evaluations are limited to the Vicuna/LLaMA series; applicability to architectures other than decoder-only remains unverified.
- Parallel MLP heads have limited capability in modeling long-range dependencies.
- The number of candidate paths $s^K$ in FTA might grow exponentially with the number of parallel heads; practical usage requires limiting the size of $s$.
- Belongs to the self-drafting category of methods, requiring access to the target LLM's hidden states, which is inapplicable to black-box API scenarios.

## Related Work & Insights

- **Medusa** (Cai et al., 2024): Prototype of parallel MLP heads, which Gumiho's parallel phase inherits.
- **Eagle/Eagle-2** (Li et al., 2024): Sequential Transformer draft model, on which Gumiho's sequential phase is based.
- **Hydra** (Ankner et al., 2024): Sequential MLP, proving that sequential outperforms parallel, but at the cost of speed.
- Insight: This hybrid approach can be extended to other multi-token prediction scenarios (e.g., multi-token prediction pre-training).
