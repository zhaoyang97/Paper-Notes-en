# From Programs to Poses: Factored Real-World Scene Generation via Learned Program Libraries

**Conference**: NeurIPS 2025
**arXiv**: [2510.10292](https://arxiv.org/abs/2510.10292)
**Code**: To be confirmed
**Area**: 3D Scene Generation / Program Synthesis
**Keywords**: 3D scene generation, program synthesis, LLM, layout program library, pose prediction, ScanNet

## TL;DR
This paper proposes FactoredScenes, which decomposes real-world 3D scene generation into a five-step factorization pipeline — learning a layout program library from synthetic data, generating scene programs via LLM, executing programs to obtain axis-aligned layouts, program-conditioned hierarchical pose prediction, and object retrieval and placement. The method achieves 38.3% FID improvement and 80.4% KID improvement on bedrooms, with human evaluators able to distinguish generated scenes from real ScanNet scenes only 67% of the time.

## Background & Motivation

**Background**: Existing 3D scene generation methods (autoregressive ATISS, diffusion-based DiffuScene, LLM-based LayoutGPT, etc.) predominantly generate axis-aligned bounding boxes, ignoring object orientation and failing to capture the appearance of "lived-in" scenes.

**Limitations of Prior Work**: (a) Real-world scene data is scarce (ScanNet contains only 707 scenes), making it infeasible to directly learn the full distribution; (b) existing methods handle only axis-aligned layouts, yet in real scenes chairs face tables and monitors face seats — pose variation is central to the sense of inhabitation; (c) LLM-based generation relies on manually designed domain languages that are difficult to generalize flexibly.

**Key Challenge**: Scenes exhibit both high-level structure (chairs arranged around a table) and noisy pose variation (each chair oriented slightly differently), requiring simultaneous modeling of structure and variation under severe data scarcity.

**Goal**: Learn to generate ScanNet-quality 3D scenes with realistic object orientations from limited real-world data.

**Key Insight**: Decompose the problem into "structure" (programs learned from large-scale synthetic data) and "variation" (poses learned from limited real data), applying different data sources and methods to different sub-problems.

**Core Idea**: Synthetic data for structural program learning + LLM for layout generation + real data for pose learning = factored real-world scene generation.

## Method

### Overall Architecture
A five-step factorization: $P(S) = P(objects|pose, program) \cdot P(pose|layout, program) \cdot P(layout=f(program)) \cdot P(program|library) \cdot P(library)$. Each step uses a distinct data source and method: $P(library)$ is learned from 3D-Front; $P(program|library)$ is generated by an LLM; $P(layout)$ is obtained via deterministic execution; $P(pose)$ is trained on ScanNet; and $P(objects)$ is realized via nearest-neighbor retrieval.

### Key Designs

1. **Program Library Learning (Wake-Sleep + LLM)**:

    - Function: Automatically discovers reusable functions capturing room structure from 3D-Front synthetic data.
    - Mechanism: In the Wake phase, an LLM serves as the recognition model (layout → program); in the Sleep phase, the LLM proposes new abstraction functions. Starting from just two initial functions, `object_instantiation` and `parallel`, the system learns functions such as `align`, `grid`, `grid_with_offset`, `symmetrical`, and `cluster_placement`.
    - Design Motivation: Eliminates the need for manual domain language design; the LLM automatically proposes functions at appropriate abstraction levels; functions learned from 3D-Front transfer directly to ScanNet, demonstrating the existence of cross-dataset universal structures in human-designed rooms.

2. **Program-Conditioned Hierarchical Pose Prediction**:

    - Function: Predicts the orientation angle $\theta$ for each object (discretized into 36 classes at 5°/bin).
    - Mechanism: Operates in two stages — primary objects (e.g., tables) predict $\theta$ from bounding box and nearest-wall encodings; secondary objects (e.g., chairs around a table) are additionally conditioned on the predicted orientations of their dependency targets and text embeddings of program functions. Multi-head self-attention processes all objects jointly.
    - Design Motivation: In real scenes, "chairs orient relative to the table" reflects a hierarchical dependency. Removing the dependency conditioning reduces secondary object accuracy from 44.2% to 39.7%.

3. **LLM Program Generation + Library Regularization**:

    - Function: Uses an LLM (GPT-o1) to generate diverse scene programs.
    - Mechanism: ScanNet scenes are first parsed into few-shot program exemplars; the LLM then generates new programs (as executable Python) constrained to the learned library functions.
    - Design Motivation: LLM common sense determines object placement while library constraints ensure structural plausibility.

### Loss & Training
- Orientation: cross-entropy loss (36-class classification).
- Oversampling of difficult scenes (those with a high proportion of hard-to-predict orientations).
- Inference: $\hat{\theta} = 5 \cdot \arg\max_k \hat{y}_{ij,k}$

## Key Experimental Results

### Main Results

| Method | Bedroom FID | Living Room FID | Bedroom KID | Living Room KID |
|--------|-------------|-----------------|-------------|-----------------|
| DiffuScene | 135.57 | 186.54 | 0.130 | 0.177 |
| ATISS | 120.27 | 176.95 | 0.117 | 0.166 |
| LayoutGPT | 109.40 | 157.69 | 0.102 | 0.142 |
| Ours w/o poses | 101.55 | 137.66 | 0.085 | 0.106 |
| Ours w/ random poses | 110.03 | 123.64 | 0.086 | 0.079 |
| **FactoredScenes** | **67.51** | **83.49** | **0.020** | **0.024** |

### Ablation Study

|---------------|-------------|------|
| w/o poses (axis-aligned) | 101.55 | Program structure alone already surpasses prior SOTA |
| w/ random poses | 110.03 | Random orientations yield worse results |
| **Full model** | **67.51** | Pose prediction is the key factor |

| Library Type | ScanNet Function Usage | ScanNet mIoU |
|--------------|------------------------|--------------|
| Inference-only | 0.34 | 0.96 |

|--------------------|------------------------|--------------------------|

### Human Evaluation
400 judgments (20 pairs × 20 participants): accuracy in selecting real ScanNet scenes was only **0.67** — evaluators failed to distinguish generated from real scenes 33% of the time.

### Key Findings
- **Program structure alone already surpasses all prior SOTA**: w/o poses FID of 101.55 < LayoutGPT's 109.40.
- **Random poses perform worse than no poses**: orientation is not simple noise — incorrect orientations cause object overlaps and implausible configurations.
- **Hierarchical dependency is critical**: secondary objects must be conditioned on primary object orientations (+11.4%).
- **Cross-dataset transfer succeeds**: library functions learned from 3D-Front transfer directly to ScanNet.

## Highlights & Insights
- **Factorization is the core contribution**: the data-scarcity challenge is decomposed into five sub-problems, each addressed with the most suitable data source and method — every module operates under its optimal conditions.
- **Wake-Sleep + LLM for library learning** is an elegant approach: a DreamCoder-style paradigm upgraded with LLMs.
- **Quantitative characterization of "lived-in" appearance**: pose prediction transforms the subjective quality of "natural-looking scenes" into a learnable objective.

## Limitations & Future Work
- LLM generation occasionally produces implausible placements (e.g., a nightstand in the middle of a bed).
- Incomplete objects in ScanNet introduce annotation errors in ground-truth orientations.
- Pose prediction is currently deterministic; future work could extend it to distributional prediction.
- The method currently handles only bedrooms and living rooms.
- Physical collision detection is not considered.

## Related Work & Insights
- **vs. LayoutGPT**: outputs only axis-aligned boxes. FactoredScenes reduces FID by 38.3% through program library constraints and a pose model.
- **vs. Holodeck**: relies on predefined domain modules. FactoredScenes automatically discovers functions via library learning.
- **vs. DreamCoder**: extends the paradigm to the 3D scene domain, replacing the neural recognition model with an LLM.
