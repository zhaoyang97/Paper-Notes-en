# TeXpert: A Multi-Level Benchmark for Evaluating LaTeX Code Generation by LLMs

**Conference**: ACL 2025  
**arXiv**: [2506.16990](https://arxiv.org/abs/2506.16990)  
**Code**: [https://github.com/knowledge-verse-ai/TeXpert](https://github.com/knowledge-verse-ai/TeXpert)  
**Area**: NLP Generation / Code Generation Evaluation  
**Keywords**: LaTeX generation, LLM evaluation, benchmark, code generation, scientific documents

## TL;DR
Proposes TeXpert, the first multi-difficulty level benchmark for systematically evaluating LLMs' capability to generate LaTeX code for scientific documents from natural language instructions. It contains 440 high-quality samples across three levels (Simple/Average/Hard). Evaluation of 9 open-source and closed-source LLMs reveals that LaTeX generation remains a significant weakness (accuracy on the Hard task is generally below 17.5%), with logical and formatting errors being the primary bottlenecks.

## Background & Motivation
LaTeX is the de facto standard for typesetting scientific documents, possessing irreplaceable advantages in handling mathematical formulas, reference management, and more. With the improvement of instruction-following capabilities in LLMs, a natural question arises: **Can LLMs generate publication-grade LaTeX code directly from natural language descriptions?**

**Limitations of Prior Work**:
- Existing works only cover narrow sub-tasks of LaTeX: the MATH dataset evaluates mathematical formula generation, STRUC-BENCH only tests tables, and im2latex-100k focuses on image-to-formula conversion.
- No existing benchmarks systematically evaluate the capability of LLMs to generate LaTeX code for various components of scientific documents (tables, figures, references, document structures, etc.).
- LaTeX templates are typically too large to generate directly and are restricted to basic commands.

**Two Practical Values**:
1. Analyzing common error patterns in LaTeX code generated by LLMs can provide signals for detecting AI-generated academic materials.
2. Clarifying the complexity boundaries of LaTeX tasks that LLMs can reliably complete helps researchers reduce typesetting effort.

## Method

### Overall Architecture
The construction of TeXpert follows a two-step pipeline: first, collecting atomic LaTeX commands commonly used in scientific documents; second, generating natural language-to-LaTeX task samples across three difficulty levels based on these commands. During evaluation, GPT-4o is used as a judge to assess the correctness of LLM-generated code and classify error types.

### Key Designs

1. **Atomic Command Collection and Classification**:

    - Extract atomic commands from Overleaf documents and LaTeX templates of academic journals (25 documents each).
    - Utilize automatic extraction via regular expressions combined with manual verification.
    - A total of 319 commands are divided into 5 categories: text formatting (86), mathematical symbols (83), document structure (75), citation and reference (39), tables and figures (36).
    - **Design Motivation**: To restrict the dataset scope through atomic commands, ensuring a focus on the actual demands of scientific writing.

2. **Three-Level Difficulty Design**:

    - **Simple (250 samples)**: Average of 115.8 characters in instructions, about 10.9 atomic commands, and 0.5 auxiliary packages.
    - **Average (150 samples)**: Average of 299.1 characters in instructions, about 51.2 atomic commands, and 3.6 auxiliary packages.
    - **Hard (40 samples)**: Average of 558.4 characters in instructions, about 85.9 atomic commands, and 6.6 auxiliary packages.
    - Each sample is manually verified to ensure that the LaTeX generation requirements are clear and consistent with the difficulty constraints.
    - **Design Motivation**: The incrementally increasing complexity can precisely locate the capability boundaries of LLMs.

3. **Evaluation Framework**:

    - Generation: Provide LLMs with prompts containing task instructions, setting fixed parameters to guarantee deterministic output.
    - Evaluation: GPT-4o serves as the judge (for GPT-4o/mini, DeepSeek v3 is used as the judge to avoid self-bias).
    - 5 classes of errors: CE (Capability Error), SE (Syntax Error), LE (Logical Error), PE (Package Error), FE (Formatting Error).
    - The Hard set additionally provides human-written and verified reference LaTeX code to assist in the evaluation.

### Loss & Training
This work does not involve model training as it is a pure evaluation benchmark. The evaluation prompts are iteratively optimized, and manual spot-checking is conducted to ensure the reliability and consistency of the judgments.

|------|----------|----------|----------|---------|----------|

### Key Findings
- **Hard tasks are a universal bottleneck**: Even GPT-4o achieves only 15% accuracy, while Claude and Gemini fail completely (0%), revealing a distinct capability cliff.
- **Logical errors are dominant** (44-59%): Primarily manifested as missing instruction requirements and incorrect structural placements, especially in multi-formula/multi-table tasks.
- **Formatting errors are unexpectedly high** (20-25%): Even large models frequently make mistakes in environment selection and table/caption formatting, indicating that model scaling is not the sole solution.
- **Package errors are worrisome**: Incorrect or incomplete package import, especially regarding reference-related packages, with Claude exhibiting the most severe issues (29.9%).
- **Open-source models are highly competitive with closed-source ones**: DeepSeek V3 and Coder 33b are close to GPT-4o in overall accuracy and even surpass it on the Hard set.

## Highlights & Insights
- **Filling the Gap**: The first systematic benchmark in the field of LaTeX code generation evaluation, complementing single-dimension works like MATH and STRUC-BENCH.
- **Quantification of Capability Boundaries**: Through the three-level difficulty design, the capability ceiling of LLMs in LaTeX generation is precisely characterized—an average difficulty of about 50-60 atomic commands and 3-4 packages is the current limit.
- **Training Data Bottleneck Hypothesis**: The ubiquity of formatting errors and package errors strongly suggests a lack of diverse LaTeX examples in LLM training data.
- **DeepSeek Coder's lead on the Hard set** indicates that specialized code training offers unique advantages for generating structured outputs.
- **Pragmatism of Evaluation Design**: Utilizing a hybrid evaluation approach of LLM-as-Judge combined with human reference code strikes a balance between cost and accuracy.

## Limitations & Future Work
- The Hard set contains only 40 samples, which limits statistical reliability.
- It only covers scientific documents, omitting other document types such as resumes and books.
- Fine-tuning models using the TeXpert dataset was not attempted.
- The impact of advanced prompting strategies (e.g., few-shot, self-debug) on performance was not explored.
- Potential biases of LLM-as-Judge itself were not fully discussed.
- Sub-item accuracies across different LaTeX command categories (formulas vs. tables vs. citations) were not analyzed.

## Related Work & Insights
- **MATH (Hendrycks et al., 2021)**, **MathBridge**, and **STEM-POM** focus on mathematical LaTeX generation, whereas TeXpert expands evaluation to comprehensive scientific document typesetting.
- **STRUC-BENCH (Tang et al., 2024)** tests table generation, while TeXpert is more comprehensive, covering all 5 categories of components.
- **Insights for Practical Workflows**: Current LLMs can only reliably handle LaTeX tasks at the Simple level (approx. 60-78% accuracy). Researchers utilizing LLMs for assisted typesetting should limit usage to generating simple components, leaving complex layouts for manual handling.
- **Potential Applications**: The error pattern analysis of TeXpert can provide features for detecting AI-generated academic materials.

## Rating
- Novelty: ⭐⭐⭐⭐ First systematic LaTeX generation benchmark, addressing an important and previously vacant problem.
- Experimental Thoroughness: ⭐⭐⭐⭐ 9 models, 3 difficulty levels, and 5 error categories analyzed, making it highly comprehensive.
- Writing Quality: ⭐⭐⭐ Clear structure, but some analyses are somewhat superficial, and discussion on Hard set statistics is insufficient.
- Value: ⭐⭐⭐⭐ Direct instructional value for LLM-assisted academic writing; the open-source dataset facilitates community research.
