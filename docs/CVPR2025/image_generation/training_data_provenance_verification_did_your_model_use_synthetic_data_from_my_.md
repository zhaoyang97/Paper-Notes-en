# Training Data Provenance Verification: Did Your Model Use Synthetic Data from My Generative Model for Training?

**Conference**: CVPR 2025  
**arXiv**: [2503.09122](https://arxiv.org/abs/2503.09122)  
**Code**: [GitHub](https://github.com/xieyc99/TrainProVe)  
**Area**: Image Generation  
**Keywords**: Data Provenance, Intellectual Property Protection, Diffusion Models, Hypothesis Testing, Synthetic Data

## TL;DR

The TrainProVe method is proposed based on generalization error bound theory. It verifies whether a suspicious model was trained on synthetic data from a specific generative model using shadow model training and hypothesis testing, achieving an accuracy of over 99%.

## Background & Motivation

High-quality open-source text-to-image models (such as Stable Diffusion) have significantly lowered the barrier to obtaining realistic images, but they also bring challenges to intellectual property (IP) protection. Infringers may use synthetic data generated by these models without authorization to train their own task-specific models.

Existing protection methods mainly focus on three scenarios: Case 1, direct theft of synthetic images (resolvable by watermarking); Case 2, training a task-identical generative model via knowledge distillation (resolvable by training data provenance); Case 3, training models for different tasks (such as classifiers) using synthetic data, which is the most challenging scenario—the defender has no access to the training data and cannot directly compare the models (as the tasks differ).

**Core Problem**: When the suspect model is a black box and performs a different task, how can one verify whether its training data originates from a specific generative model? This is an important but previously unexplored problem.

Currently, no method can address Case 3. This paper proposes the first feasible solution.

## Method

### Overall Architecture

TrainProVe consists of three phases: (1) using the defender's generative model $G_d$ to generate a shadow dataset $\mathcal{D}_{sdw}$ and a validation dataset $\mathcal{D}_v$; (2) training a shadow model $M_{sdw}$ with the shadow data; (3) performing a hypothesis test on the performance of the shadow model and the suspect model on the validation dataset to determine if the suspect model is benign. The entire process requires only the defender's own generative model and does not require access to the suspect model's internals.

### Key Design 1: Theoretical Foundation Based on Generalization Error Bounds

**Function**: Provides theoretical support for the verification method.

**Mechanism**: Using the generalization error bound theorem in domain adaptation, for two models $M$ and $\hat{M}$ performing the same task, the difference in their generalization errors on the target domain $T$ is constrained by the distance between their training data distributions. The theorem proves that if the training data of $\hat{M}$ comes from the same generative model $G$ as $M$, the upper bound of $\sup|\Delta\epsilon_T|$ is smaller; when the data comes from a different source, the upper bound is larger. Specifically, $\sup_{P_2 = P(\mathbf{x}|G,\mathcal{T}_2)}|\Delta\epsilon_T| \leq \sup_{P_2 \perp G}|\Delta\epsilon_T|$.

**Design Motivation**: A reliable theoretical basis is needed to distinguish between "same-source training" and "different-source training". The generalization error bound provides such a mathematical guarantee—same-source models perform more similarly on same-source validation data.

### Key Design 2: Shadow Model Strategy

**Function**: Build comparable baseline models.

**Mechanism**: The defender uses their own generative model $G_d$, combined with a text prompt $\mathcal{T}_{sdw}$ (e.g., `"a {class}"`) different from what the suspect might use, to generate a shadow dataset and train the shadow model $M_{sdw}$. The validation dataset is generated using another set of prompts $\mathcal{T}_v$ (e.g., `"a photo of a {class}"`). The key is that both the shadow and validation data originate from the exact same generative model but use different prompts, ensuring distribution difference while maintaining same-source similarity.

**Design Motivation**: A direct comparison between the suspect model and the generative model is infeasible (as tasks differ); thus, an "intermediary bridge" is needed—a shadow model conducting the same task as the suspect model, with training data known to originate from $G_d$.

### Key Design 3: One-Sided Grubbs Hypothesis Testing

**Function**: Statistically verify whether the suspect model is of the same source as the shadow model.

**Mechanism**: Input the validation set into both models in batches to calculate the set of accuracies per batch, $\mathcal{A}_{sdw}$ and $\mathcal{A}_{sus}$. A one-sided Grubbs test is employed to determine whether $\text{mean}(\mathcal{A}_{sus})$ is an anomalously low value in $\mathcal{A}_{sdw}$. If the null hypothesis $H_0$ is rejected (meaning the suspect model's accuracy is significantly lower than that of the shadow model), the suspect model is judged to be benign (did not use data from $G_d$); otherwise, it is flagged as an infringement.

**Design Motivation**: A robust statistical method is required to distinguish "similar" vs "dissimilar". The Grubbs test is particularly suited for small-sample outlier detection and is configured as a one-sided test (solely focusing on whether accuracy is significantly lower than expected) to avoid misclassifications from two-sided testing.

### Loss & Training

The shadow model is trained using the standard cross-entropy loss. The proposed method requires no extra loss function design, as its core lies in statistical testing rather than the optimization process.

## Key Experimental Results

### Main Results (Verification Performance on Different Datasets)

| Dataset | Method | Avg Acc | Avg F1 | Avg AUC |
|--------|------|---------|--------|---------|
| CIFAR10 | Random | 0.500 | 0.286 | 0.500 |
| CIFAR10 | Han et al. | 0.768 | 0.579 | 0.731 |
| CIFAR10 | TrainProVe-Ent | 0.868 | 0.774 | 0.902 |
| CIFAR10 | **TrainProVe** | **0.997** | **0.992** | **0.998** |
| CIFAR100 | Han et al. | 0.730 | 0.548 | 0.703 |
| CIFAR100 | **TrainProVe** | **0.992** | **0.979** | **0.981** |
| ImageNet-100 | Han et al. | 0.671 | 0.425 | 0.645 |
| ImageNet-100 | **TrainProVe** | **0.786** | **0.495** | **0.769** |

### Ablation Study (Impact of Shadow Model Architecture, CIFAR10)

| Shadow Model Architecture | Avg Acc | Avg F1 | Avg AUC |
|-------------|---------|--------|---------|
| ResNet18 | 0.997 | 0.992 | 0.998 |
| ConvNeXt-B | 0.995 | 0.989 | 0.997 |
| Swin-B | 0.997 | 0.992 | 0.998 |

### Key Findings

1. **Near-Perfect on CIFAR10**: TrainProVe achieves an average accuracy of 99.7% across four text-to-image models (SD v1.4, LCM, PixArt-α, Stable Cascade), significantly outperforming the closest method by Han et al. (76.8%).
2. **Architecture Agnosticism**: High performance is maintained whether the shadow model employs a CNN (ResNet18/ConvNeXt-B) or a Transformer (Swin-B), demonstrating the robustness of the method.
3. **Feasible in Black-Box Scenarios**: Verification is completed solely by obtaining predicted labels from the suspect model via API, requesting no internal details of the model.
4. **Single Model Requirement**: In contrast to Han et al. which requires multiple generative models, TrainProVe only requires the defender's own generative model.

## Highlights & Insights

- **Strong Novelty**: As the first method to tackle the provenance problem of synthetic training data (Case 3), it fills an important research gap.
- **Solid Theoretical Foundation**: Built on rigorous mathematical derivations of generalization error bounds rather than empirical designs.
- **High Practicality**: The black-box setting, single-model requirement, and statistical testing framework fit well within the forensic demands of real-world copyright disputes.

## Limitations & Future Work

- **Performance Drop on ImageNet-100**: The accuracy drops to 78.6%, suggesting that performance needs enhancement in complex scenarios with numerous classes.
- **Classification Models Only**: Currently, only classification models are supported for suspect testing, without extension to other tasks like detection or segmentation.
- **Strong Assumption**: It assumes the defender knows the task category of the suspect model (e.g., the predictive label set $\mathcal{C}$), which might not be completely known in real-world scenarios.
- Future research can explore provenance verification for non-classification tasks and identification of mixed, multi-source training data.

## Related Work & Insights

- **Watermarking Methods**: Suitable only for Case 1 involving direct image theft, failing to address indirect usage issues.
- **Domain Adaptation Theory**: Generalization error bounds are widely used in domain adaptation; this work innovatively adopts them for data provenance verification.
- **Insight**: The insight that "same-source models share similar generalization capability" can be extended to more IP protection situations, such as detecting model distillation.

## Rating

⭐⭐⭐⭐ — The problem definition is novel and practical, with a solid theoretical foundation and excellent results on CIFAR. However, the performance degradation on ImageNet-100 highlights scalability concerns, and the limitation to classification tasks reduces overall utility.
