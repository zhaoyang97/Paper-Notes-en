# SERM: Self-Evolving Relevance Model with Agent-Driven Learning from Massive Query Streams

**Conference**: ACL 2026 Findings  
**arXiv**: [2601.09515](https://arxiv.org/abs/2601.09515)  
**Code**: None  
**Area**: Multilingual Translation  
**Keywords**: Search Relevance, Self-evolving Model, Multi-agent Labeling, Query Stream Adaptation, Distribution Shift

## TL;DR

Ours proposes the SERM framework, which continuously evolves search relevance models from massive real-world query streams using a multi-agent sample miner and a multi-agent relevance annotator. After three iterations, it achieved a +2.99 NDCG@1 improvement on an industrial search platform and significantly enhanced user retention in online A/B tests.

## Background & Motivation

**Background**: Search relevance modeling is the core of information retrieval, aiming to rank candidate documents for a given query. Traditional methods employ discriminative modeling (encoder + scoring function), while recent research utilizes the generative capabilities of LLMs to produce relevance judgments and rationales directly. The standard training pipeline consists of two stages: "continuous pre-training + supervised fine-tuning (SFT)."

**Limitations of Prior Work**: Real-world query distributions evolve dynamically and continuously—users constantly introduce new expressions, cultural references, and emerging linguistic patterns. Static training data fails to cover these changes, leading to insufficient model generalization. For example, a query like "remember me pets arriving on 10/27" contains subtle semantics (commemorating a deceased pet vs. general pet relocation) that are difficult for models to capture.

**Key Challenge**: Self-evolution is a promising direction, but it faces two challenges in industrial-scale query streams: (C1) informative samples are extremely sparse and difficult to identify within massive query volumes; (C2) pseudo-labels generated by the model itself can be unreliable, leading to error accumulation.

**Goal**: To design a search relevance model capable of continuous self-evolution from massive query streams while addressing the challenges of sample discovery and label reliability.

**Key Insight**: Utilize a multi-agent framework where multiple roles perform specialized tasks: an environment feedback agent uses user click/dwell signals to discover difficult samples, an introspection feedback agent uses model inconsistencies and uncertainties to identify weaknesses, and a multi-agent annotator generates reliable labels through a two-level consensus mechanism.

**Core Idea**: A multi-agent sample miner is used to efficiently filter hard samples from massive query streams that the model needs most. Then, a multi-agent annotator (multi-LLM + internal/external consensus) generates reliable labels for these samples to achieve iterative self-evolution.

## Method

### Overall Architecture

SERM is built upon an LLM-based generative relevance model (inputting query+doc to generate relevance scores and rationales). The self-evolution loop occurs bi-weekly: (1) The multi-agent sample miner selects approximately 700K hard samples from the new query stream; (2) The multi-agent relevance annotator generates reliable labels for these samples; (3) The model is retrained by mixing new data with existing SFT data to prevent catastrophic forgetting.

### Key Designs

1.  **Multi-agent Sample Miner (MSM)**:
    *   **Function**: Efficiently identify hard samples from massive query streams that are most valuable for model improvement.
    *   **Mechanism**: Deploys four types of complementary agents. (a) User feedback agent: detects contradictory pairs where "user engagement is strongly positive (clicks/high dwell) but model confidence is low"; (b) Click model feedback agent: uses a pre-trained click model to compensate for position bias and sparsity of raw click signals; (c) Model disagreement agent: generates K judgments for the same pair using temperature sampling and calculates the maximum disagreement $MD(q,d) = \max_{i,j} |f^i(q,d) - f^j(q,d)|$; (d) Model uncertainty agent: calculates the entropy of the label distribution $MU(q,d) = -\sum_y \Pr(y|q,d) \log \Pr(y|q,d)$.
    *   **Design Motivation**: A single signal is insufficient—user feedback is biased and sparse, while internal signals cannot capture external demand shifts. The union of multiple agents covers different types of hard samples.

2.  **Multi-agent Relevance Annotator (MRA)**:
    *   **Function**: Generate reliable relevance labels and rationales for hard samples.
    *   **Mechanism**: A two-level consensus framework. (a) Internal consensus: Each LLM (e.g., GPT-4o, Gemini 2.5 Pro) first retrieves external knowledge, then uses multi-path CoT to generate independent reasoning paths, producing stable labels via majority voting; (b) Cross-agent consensus: Only samples where multiple LLMs reach an agreement are retained, and all reasoning paths supporting the final label are integrated into a unified rationale.
    *   **Design Motivation**: Unlike knowledge distillation, MRA provides evolutionary feedback. It filters noisy labels via cross-model consensus to avoid error propagation in self-training. Internal consensus addresses the randomness of single LLM outputs, while cross-agent consensus addresses systemic biases of individual models.

3.  **Iterative Self-evolving Training**:
    *   **Function**: Continuously improve model performance through multiple iterations.
    *   **Mechanism**: In each iteration, the model is retrained by mixing newly generated data, historical iteration data, and original SFT data. The process runs every two weeks to ensure sufficient query distribution shift coverage. It can be distilled into smaller models (0.5B) to meet latency requirements.
    *   **Design Motivation**: Mixed training prevents catastrophic forgetting, while periodic updates ensure the model keeps pace with query distribution evolution.

### Loss & Training

The generative modeling objective is $\mathcal{L}_g = -\mathbb{E} \log \Pr_\theta(y|q,d)$, where the model outputs a relevance score (0-3) after generating a rationale. Three types of data are mixed during iterative training to prevent forgetting. Distillation utilizes KL divergence loss.

## Key Experimental Results

### Main Results

| Method | Model | Germanic NDCG@1 | Romance NDCG@1 | Minor Lang NDCG@1 |
| :--- | :--- | :--- | :--- | :--- |
| CT+SFT | 7B | 84.74 | 85.61 | 82.02 |
| Self-Training Iter3 | 7B | 84.78 | 85.58 | 82.20 |
| SERM Iter3 | 7B | 87.56 | 88.14 | 84.99 |
| CT+SFT | 1.5B | 84.59 | 85.99 | 81.75 |
| SERM Iter3 | 1.5B | 87.30 | 87.83 | 84.75 |

### Online A/B Tests

| Metric | Gain | P-value |
| :--- | :--- | :--- |
| 14-day Retention | +0.0359% | 0.0278 |
| Negative User Feedback | -1.2081% | 0.0001 |
| Query Reformulation Rate | -0.0839% | 0.0023 |
| Reformulation Rate (Long-tail) | -0.1312% | 0.0015 |

### Key Findings

*   After three iterations, SERM improved NDCG@1 by +2.82 (7B) / +2.71 (1.5B), while self-training only improved by +0.04 / +0.45. Furthermore, self-training exhibited degradation (error propagation) in the third iteration.
*   Distillation effectiveness: SERM distilled to a 0.5B model outperformed self-training distillation, indicating that more reliable labels were transferred to the smaller model.
*   Online A/B tests showed significant improvements in user experience—negative feedback decreased by 1.2% and 14-day retention increased by 0.036%, which is highly significant on a platform with billions of daily requests.
*   The instability of self-training was particularly evident in the third iteration (Germanic NDCG@1 dropped from 84.95 back to 84.78), validating the issue of pseudo-label error accumulation.

## Highlights & Insights

*   **Sophisticated multi-agent collaboration**: Environment feedback (user signals) and introspection feedback (model uncertainty) complement each other—the former captures external information unknown to the model, while the latter identifies cognitive gaps. This design is transferable to any system requiring continuous learning from data streams.
*   **Two-level consensus labeling mechanism**: Internal multi-path voting combined with cross-model consensus filters noise layer by layer. Compared to simple knowledge distillation or self-training, this mechanism fundamentally addresses the unreliability of pseudo-labels.
*   **Industrial-scale validation**: Online A/B tests were conducted on a real search platform with billions of daily requests, providing highly persuasive results.

## Limitations & Future Work

*   Reliance on GPT-4o and Gemini 2.5 Pro as annotators results in high API costs, and the annotators themselves may harbor biases.
*   The bi-weekly iteration frequency might not keep pace with rapid query distribution shifts caused by sudden trending events.
*   Currently validated only on document search; extending to multi-modal scenarios like video or image search requires additional adaptation.
*   Future explorations: Reducing reliance on external LLMs (using the internal model as one of the annotators for hybrid consensus) and introducing active learning strategies for more efficient sample labeling.

## Related Work & Insights

*   **vs Self-Training**: Self-training uses the model's own predictions as pseudo-labels, leading to degradation after three iterations; SERM achieves stable improvements through reliable labels provided by external multi-LLM consensus.
*   **vs Knowledge Distillation**: Distillation is a unidirectional knowledge transfer from a fixed teacher to a student; SERM is an iterative evolutionary feedback loop—the model in each round is stronger than the last, and the annotation quality improves accordingly.
