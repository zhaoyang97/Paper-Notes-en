# SCALE: Selective Resource Allocation for Overcoming Performance Bottlenecks in Mathematical Test-time Scaling

**Conference**: AAAI 2026
**arXiv**: [2512.00466](https://arxiv.org/abs/2512.00466)  
**Code**: [https://github.com/XiaoYang66/DualThinking](https://github.com/XiaoYang66/DualThinking)  
**Area**: LLM Reasoning
**Keywords**: Test-time compute, dual-process theory, mathematical reasoning, resource allocation, sub-problem decomposition

## TL;DR
Grounded in the dual-process theory from cognitive science, SCALE decomposes mathematical problems into sub-problems and allocates compute resources according to difficulty (System 1 for fast computation vs. System 2 for deep reasoning). On AIME25, it improves Qwen3-32B from 57.50% to 71.25% while reducing token consumption by 33–53% compared to InftyThink.

## Background & Motivation

**Background**: Test-time compute scaling (e.g., majority voting, long chain-of-thought reasoning) has become an effective paradigm for improving LLM mathematical reasoning, but existing methods allocate computational resources uniformly across all sub-problems.

**Limitations of Prior Work**: Uniform allocation wastes a large number of tokens on deep reasoning for trivial computations (e.g., $\sqrt{16}=4$), while difficult algebraic derivations receive insufficient computational budget. This "one-size-fits-all" strategy is the fundamental bottleneck of test-time scaling.

**Key Challenge**: Increasing the total token budget yields diminishing returns, as marginal computation is largely wasted on simple steps.

**Key Insight**: Drawing inspiration from the dual-process theory in cognitive science — humans use System 1 for simple intuitive judgments and System 2 for complex problems requiring deliberate reasoning.

**Core Idea**: Fine-grained, sub-problem-level allocation of computational resources — answer simple sub-problems quickly, reason deeply over difficult ones.

## Method

### Overall Architecture
Mathematical problem → Decomposition into ordered sub-problems → Difficulty estimation $d_i \in [0,1]$ for each sub-problem → Mode assignment based on threshold τ (System 1 / System 2) → Sequential execution with context propagation → Answer aggregation.

### Key Designs

1. **Problem Decomposition**:

    - Function: Splits the mathematical problem into a sequence of sub-problems with explicit logical dependencies.
    - Mechanism: Multiple decomposition candidates are generated and evaluated by an LLM (on correctness, clarity, completeness, and relevance) to select the optimal one.

2. **Difficulty Estimation**:

    - Function: Computes a difficulty score for each sub-problem.
    - Mechanism: $d_i \in [0,1]$, accounting for computational complexity, mathematical depth, number of reasoning steps, and solution uncertainty. Evaluated using cumulative context (original problem + all preceding solutions).

3. **Adaptive Mode Selection**:

    - $d_i \leq \tau$: System 1 — fast, direct computation.
    - $d_i > \tau$: System 2 — step-by-step CoT deep reasoning.
    - Optimal τ = 0.2; approximately 75% of sub-problems are assigned to System 2.

4. **Context Propagation**:

    - Function: Executes sub-problems sequentially, with each subsequent sub-problem conditioned on all preceding solutions.
    - Mechanism: $\mathbb{P}(\text{Answer}|P) = \prod_i P(\mathcal{S}(s_i) | C_i, s_i)$

### Loss & Training
- SCALE is a training-free inference framework that directly leverages existing reasoning models.
- Reasoning trajectories generated by SCALE can be used as synthetic data to fine-tune non-reasoning models.

## Key Experimental Results

### Main Results

| Model | Benchmark | SCALE | CoT Baseline | Gain | Tokens |
|-------|-----------|-------|--------------|------|--------|
| Qwen3-32B | AIME24 | **82.92%** | 73.33% | +9.59pp | 25,581 |
| Qwen3-32B | AIME25 | **71.25%** | 57.50% | +13.75pp | 26,643 |
| QwQ | AIME24 | **79.40%** | 75.00% | +4.40pp | 29,812 |
| QwQ | AIME25 | **70.21%** | 63.33% | +6.88pp | 33,965 |

Fine-tuning non-reasoning models: Llama3.3-70B on AIME24 improves from 24.58% to **63.51%** (+38.93pp).

### Ablation Study (τ Sensitivity, Qwen3-32B)

| τ | AIME24 | AIME25 | Hard% | Note |
|---|--------|--------|-------|------|
| 0.2 | **78.75%** | **63.75%** | 75.6% | Optimal: majority of sub-problems use System 2 |
| 0.4 | 73.33% | 55.66% | 51.7% | Notable degradation |
| 0.7 | 50.00% | 39.17% | 17.7% | Mostly System 1; severe performance collapse |

### Key Findings
- **Significant token efficiency**: SCALE saves 33–53% tokens compared to InftyThink while achieving higher accuracy.
- **τ = 0.2 is optimal**: This indicates that the majority of mathematical reasoning sub-steps genuinely require deep deliberation, with only a small fraction amenable to fast solving.
- **Synthetic data is effective**: Fine-tuning non-reasoning models with SCALE trajectories yields substantial gains (+38.93pp), confirming the high quality of SCALE-generated reasoning processes.

## Highlights & Insights
- **Operationalizing dual-process theory**: Translates cognitive science concepts into a practical algorithm via sub-problem difficulty estimation and mode switching.
- **Win-win on token efficiency and accuracy**: Rather than simply trading more tokens for higher accuracy, SCALE achieves higher accuracy with fewer tokens.

## Limitations & Future Work
- Problem decomposition and difficulty estimation both rely on the LLM's own capabilities; decomposition errors can cascade through subsequent sub-problems.
- Validation is limited to mathematical competition problems; generalization to other reasoning tasks (e.g., code, logic) remains to be confirmed.
- The threshold τ requires manual tuning per task and model.

## Related Work & Insights
- **vs. Majority Voting**: Majority voting performs undifferentiated repeated sampling, whereas SCALE strategically allocates compute resources, achieving 2–3× greater efficiency.
- **vs. Long-reasoning methods (e.g., InftyThink)**: These methods increase total reasoning length, while SCALE performs fine-grained allocation at the sub-problem granularity.
