# DC-Solver: Improving Predictor-Corrector Diffusion Sampler via Dynamic Compensation

**Conference**: ECCV2024  
**arXiv**: [2409.03755](https://arxiv.org/abs/2409.03755)  
**Code**: [wl-zhao/DC-Solver](https://github.com/wl-zhao/DC-Solver)  
**Area**: Others  
**Keywords**: diffusion model, Fast Sampling, ODE Solver, Predictor-Corrector, Dynamic Compensation

## TL;DR

DC-Solver is proposed to alleviate the misalignment issue in predictor-corrector diffusion samplers through Dynamic Compensation. It optimizes compensation ratios using only 10 data points and achieves instant generalization to unseen NFE/CFG configurations via Cascade Polynomial Regression (CPR).

## Background & Motivation

Diffusion probabilistic models (DPMs) perform exceptionally well in visual generation, but their sampling process requires multiple forward evaluations of the denoising network, resulting in high computational costs. Existing fast samplers such as DPM-Solver++, DEIS, and UniPC significantly reduce the required number of function evaluations (NFEs) by solving the diffusion ODE. Among them, UniPC introduces a predictor-corrector paradigm to further enhance sampling quality. However, the predictor-corrector framework suffers from an inherent **misalignment issue**: the corrector step refines the intermediate result $\tilde{x}_{t_i}^c$, but the model output $\epsilon_\theta(\tilde{x}_{t_i}, t_i)$ stored in the buffer $Q$ is still computed based on the pre-refinement result $\tilde{x}_{t_i}$, creating an inconsistency between the two. This misalignment is further amplified when using a large classifier-free guidance (CFG) scale.

Although directly recomputing $\epsilon_\theta(\tilde{x}_{t_i}^c, t_i)$ can resolve this issue, it introduces an extra network forward pass, doubling the computational cost. Therefore, how to alleviate this misalignment without increasing the NFE is the core motivation of this work.

## Core Problem

1. **Misalignment Issue**: In predictor-corrector samplers, there is an inconsistency between the filtered intermediate result refined by the corrector and the reused model outputs stored in the buffer, which degrades the sampling accuracy of subsequent steps.
2. **CFG Amplification Effect**: The linear combination of classifier-free guidance $\bar{\epsilon}_\theta = s \cdot \epsilon_\theta(x_t, t, c) + (1-s) \cdot \epsilon_\theta(x_t, t, \varnothing)$ amplifies the negative impact of misalignment.
3. **NFE/CFG Generalization**: The optimized compensation ratios are specific to a particular NFE and CFG configuration, requiring a re-search whenever users change the settings.

## Method

### 1. Dynamic Compensation

The core idea is to approximate $\epsilon_\theta(\tilde{x}_{t_i}^c, t_i)$ using the historical model outputs already in the buffer $Q$ via Lagrange interpolation, thereby avoiding extra network forward passes.

Given a compensation ratio $\rho_i$, a new timestep is defined as $t_i' = \rho_i t_i + (1 - \rho_i) t_{i-1}$. Then, Lagrange interpolation is performed on the $K+1$ historical model outputs in the buffer:

$$\hat{\epsilon}^{\rho_i}(\tilde{x}_{t_i}^c, t_i) = \sum_{k=0}^{K} \prod_{\substack{0 \le l \le K \\ l \ne k}} \frac{t_i' - t_{i-l}}{t_{i-k} - t_{i-l}} \epsilon_\theta(\tilde{x}_{t_{i-k}}, t_{i-k})$$

- When $\rho_i = 1.0$, the estimation degenerates to the original $\epsilon_\theta(\tilde{x}_{t_i}, t_i)$ (i.e., no compensation).
- By adjusting $\rho_i$, one can switch between interpolation and extrapolation to find a better approximation.
- Experiments demonstrate that $K=2$ (second-order Lagrange interpolation) achieves the best performance.

### 2. Compensation Ratio Search

The compensation ratio $\rho_i$ at each step is treated as a learnable parameter, optimized by minimizing the $\ell_2$ distance between the sampled trajectory and the ground truth trajectory:

$$\rho_i^* = \arg\min_{\rho_i} \mathbb{E} \| \tilde{x}_{t_{i+1}}^c(\tilde{x}_{t_i}^c, Q^{\rho_i}) - x_{t_{i+1}}^{GT} \|_2^2$$

Key designs:

- Ground truth trajectories are generated by 999-step DDIM (conditional sampling) or 200-step DDIM (unconditional sampling).
- Only $N=10$ initial noise data points are needed.
- Optimized using AdamW for $L=40$ iterations, which takes about 5 minutes on a single GPU.
- The first two steps skip compensation ($\rho_0 = \rho_1 = 1.0$) due to insufficient historical data in the buffer.

### 3. Cascade Polynomial Regression (CPR)

The authors observe that the optimal compensation ratios vary approximately continuously with NFE and CFG. Thus, CPR is proposed to instantly predict compensation ratios for any configuration without running the search again:

$$\hat{\rho}_i^* = f_3^{(p_3)}(i \mid \phi^{(3)})$$

where the coefficients of $\phi^{(3)}$ are determined by a polynomial of $\text{CFG}$ denoted as $f_2^{(p_2)}$, and the coefficients of $f_2$ are in turn determined by a polynomial of $\text{NFE}$ denoted as $f_1^{(p_1)}$, forming a three-level cascade structure. The hyperparameters are set to $p_1 = p_2 = 2$ and $p_3 = 4$. By searching the compensation ratios on only a few NFE/CFG configurations, one can fit the CPR parameters using `scipy.curve_fit` and generalize to unseen configurations.

### 4. Plug-and-Play Characteristic

Dynamic compensation is not only suitable for predictor-corrector samplers (e.g., UniPC) but can also serve as a plug-and-play module to boost the performance of predictor-only samplers (e.g., DDIM, DPM-Solver++).

## Key Experimental Results

### Unconditional Sampling (FID↓)

| Method | FFHQ NFE=5 | FFHQ NFE=10 | LSUN-Church NFE=5 | LSUN-Bedroom NFE=5 |
|------|-----------|------------|-------------------|-------------------|
| UniPC | 18.66 | 6.99 | - | - |
| **DC-Solver** | **10.38** | **6.82** | - | - |

DC-Solver reduces the FID on FFHQ from 18.66 to 10.38 (a reduction of 8.28) at NFE=5.

### Conditional Sampling (MSE↓, SD2.1, CFG=7.5)

| Method | NFE=5 | NFE=10 |
|------|-------|--------|
| DPM-Solver++| 0.443 | 0.370 |
| DEIS | 0.436 | 0.368 |
| UniPC | 0.434 | 0.373 |
| **DC-Solver** | **0.394** | **0.294** |

### Cross-Model Generalization (NFE=5, default CFG for each model)

| Model | DPM-Solver++ | UniPC | DC-Solver |
|------|-------------|-------|-----------|
| SD1.4 (512²) | 0.803 | 0.813 | **0.760** |
| SD2.1 (768²) | 0.443 | 0.434 | **0.394** |
| SDXL (1024²) | 0.745 | 0.718 | **0.689** |

### Ablation Study Key Points

- **Compensation Method**: Dynamic compensation ($\rho_i = \rho_i^*$) significantly outperforms static compensation ($\rho_i \equiv 1.1$), which in turn outperforms no compensation ($\rho_i \equiv 1.0$).
- **Number of Data Points**: $N=10$ is sufficient, and increasing it to 20 or 30 yields marginal gains.
- **Interpolation Order**: $K=2$ is optimal; both $K=1$ and $K=3$ yield worse performance.
- **Optimization Iterations**: 40 iterations are sufficient for convergence, taking approximately 22.2 seconds per step.

## Highlights & Insights

1. **Elegant Problem Analysis**: The misalignment issue in predictor-corrector framework is clearly identified and formalized, and the proposed solution is simple yet effective.
2. **Extremely Low Search Cost**: Needs only 10 data points, 40 iterations, and 5 minutes on a single GPU, significantly superior to DPM-Solver-v3 (which requires 1024 data points, 8 GPUs for 11 hours, and 125MB storage).
3. **Zero-Cost Generalization via CPR**: The three-level cascade polynomial regression can instantly predict compensation ratios for any NFE/CFG configuration without re-searching.
4. **Broad Applicability**: Effective on SD1.4/1.5/2.1/SDXL, supporting resolutions from 512² to 1024², and compatible with different parameterization schemes ($\epsilon$-prediction, $v$-prediction).
5. **Plug-and-Play**: Dynamic compensation can simultaneously boost both predictor-only and predictor-corrector samplers.

## Limitations & Future Work

1. **Requirement of Ground Truth Trajectories**: The search phase relies on ground truth trajectories generated by 999-step DDIM, which, although required only once, still incurs an upfront cost.
2. **ODE Sampler Limitation**: The method focuses on ODE solvers, and its applicability to SDE samplers remains unexplored.
3. **CPR Generalization Boundary**: The extrapolation capability of the cascade polynomial regression might be limited under extreme NFE/CFG configurations.
4. **Combination with Distillation Methods**: The complementarity with training-based acceleration methods like consistency distillation has not been explored.
5. **Area Classified as Others**: In fact, it is a general method for accelerating diffusion models, holding broad value in the field of image generation.

## Related Work & Insights

| Method | Type | Requires Training | Extra NFE | Generalizes NFE/CFG | Search Cost |
|------|------|--------|---------|-------------|----------|
| DDIM | predictor-only | No | No | Inherent | None |
| DPM-Solver++ | predictor-only | No | No | Inherent | None |
| UniPC | predictor-corrector | No | No | Inherent | None |
| DPM-Solver-v3 | Learned parameterization | Yes | No | Requires retraining | 8 GPUs × 11 h |
| **DC-Solver** | predictor-corrector+DC | Lightweight search | No | Instant prediction via CPR | 1 GPU × 5 min |

The core advantage of DC-Solver lies in achieving significant sampling quality improvements at an extremely low cost, while maintaining flexible generalization capabilities across different configurations via CPR.

## Related Work & Insights

1. **Lagrange Interpolation Concept**: Reusing historical sampling points for interpolation/extrapolation to approximate target function values is a concept that can be extended to other numerical solving scenarios requiring a reduced number of function evaluations.
2. **Lightweight Search Paradigm**: Finding near-optimal hyperparameters with only a few data points and iterations showcases a "less is more" design philosophy, especially when compared to the heavy training in DPM-Solver-v3.
3. **Practicality of Cascaded Regression**: CPR generalizes discrete search results into continuous predictions, a methodology that can be applied to other scenarios requiring rapid prediction of optimal configurations in multi-dimensional hyperparameter spaces.
