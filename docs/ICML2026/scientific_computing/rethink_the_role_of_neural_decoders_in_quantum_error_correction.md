# Rethink the Role of Neural Decoders in Quantum Error Correction

**Conference**: ICML 2026  
**arXiv**: [2605.12046](https://arxiv.org/abs/2605.12046)  
**Code**: Not yet released  
**Area**: Quantum Error Correction / Neural Compression & Hardware Deployment  
**Keywords**: Surface code, neural decoder, FPGA, INT4 quantization, inductive bias

## TL;DR
This work systematically re-implements five types of neural decoders—MLP, 3D-CNN, TCN, Transformer, and GNN—on surface codes with $d\le9$, and incorporates "quantization + pruning + FPGA resource modeling" as first-class citizens in the training pipeline. The conclusion is: recent decoding performance is dominated by data volume rather than architectural complexity, and INT4 + QAT is a necessary prerequisite for achieving microsecond-level real-time decoding.

## Background & Motivation
**Background**: In quantum error correction (QEC), the surface code combined with real-time decoding is considered a key algorithmic primitive for fault-tolerant quantum computing. Traditional methods like MWPM and BP each excel in either accuracy or speed, while recent neural decoders (AlphaQubit, TCN, GNN-BP, etc.) are published with "high accuracy" as their main selling point.

**Limitations of Prior Work**: Existing neural decoders generally only compare logical error rates, rarely discussing real deployment constraints such as microsecond-level latency, FPGA resource usage, or low-bitwidth quantization. Moreover, it has never been systematically clarified whether reported improvements stem from architectural innovation or simply larger training sets.

**Key Challenge**: QEC decoding must physically satisfy two conflicting requirements—accuracy must be high enough to "exponentially suppress" logical errors, yet inference must complete within $\sim 1\mu s$ to match the coherence window of superconducting qubits. Previous works optimize only one side, resulting in SOTA models in papers that are infeasible on hardware.

**Goal**: Treat accuracy and latency as two sides of the same objective, and answer two concrete questions—Q1: Is performance gain driven by architecture or data? Q2: How can neural decoders actually complete inference on FPGA within the required time?

**Key Insight**: Using "surface code + Z-memory experiments + binary classification objective" as a unified benchmark, the five representative architectures are re-implemented in a de-engineered manner, paired with an end-to-end pruning + PTQ/QAT compression pipeline and FPGA resource modeling, forcing all methods to be scrutinized under both "accuracy + latency".

**Core Idea**: Replace "stacking architectures + post-hoc compression" with "data-first + moderate inductive bias + INT4 QAT", demonstrating that small models with $\sim 10^5$ parameters can already approach performance saturation and meet FPGA real-time constraints for $d\le9$.

## Method

### Overall Architecture
Unified input: The $r\times(d^2-1)$ spatiotemporal syndrome tensor $s$ generated by surface code Z-memory experiments. Unified objective: Binary classification $f(s;\theta)\in[0,1]$ to predict whether a logical flip occurs. The pipeline consists of three steps: 1) Train five architectures (MLP/dilated 3D-CNN/TCN/Transformer/GNN) on large-scale Stim simulation datasets, with fine-tuning on public Sycamore data; 2) End-to-end compression: first PTQ for feasibility probing, then QAT to INT4, combined with unstructured magnitude pruning and sparse fine-tuning; 3) FPGA resource estimation: decompose the network into INT4 MACs, map to LUT/DSP/BRAM resources to determine if it fits on a single chip and meets timing.

### Key Designs

1. **Unified Comparison of Five Architectures with Inductive Biases**:

    - **Function**: Assign the "locality + temporality + topology" required for surface code decoding to networks with different inductive biases, quantifying the relationship between bias and performance.
    - **Mechanism**: MLP flattens $s$ as a zero-bias baseline; 3D-CNN uses $3\times3\times3$ dilated convolutions to preserve spatiotemporal resolution, avoiding pooling that would harm error localization; TCN processes space with 2D conv and time with 1D conv, avoiding RNN saturation at low bitwidth; Transformer uses a convolutional tokenizer plus positional encoding instead of direct binary linear projection, mitigating embedding degradation for sparse syndromes; GNN performs learnable message passing on the Tanner graph as a "neural BP", alleviating BP oscillations caused by short cycles in the surface code.
    - **Design Motivation**: Ensure fair comparison of five representative biases on the same dataset, batching, and ground truth, thoroughly decoupling "architecture vs data" to answer Q1.

2. **Three-Stage Compression: PTQ → QAT → Pruning**:

    - **Function**: Compress the network to INT4 + high sparsity without sacrificing decoding accuracy, enabling MACs to be implemented with FPGA LUTs instead of scarce DSPs.
    - **Mechanism**: Use symmetric uniform quantization $x_{int} = \mathrm{clamp}(\lfloor x/\eta\rceil, -2^{b-1}, 2^{b-1}-1)\cdot\eta$, with per-channel weights and per-tensor activations. PTQ is first used as a feasibility probe; INT4 typically causes a "cliff" in performance, so QAT is employed, using a straight-through estimator to let FP32 latent weights learn quantization-noise-robust minima; then, unstructured pruning is applied on quantized networks based on integer magnitude (using a threshold $\tau_k$ and binary mask), followed by sparsity-aware fine-tuning.
    - **Design Motivation**: FPGAs have very few DSPs but abundant LUTs; INT4 allows multiplications to be implemented in LUTs, and static zero weights can be trimmed by synthesis tools. This "hardware-friendly + training-aware" combination is key to fitting neural decoders into the microsecond window.

3. **Reverse Model Design Constrained by FPGA Resource Estimation**:

    - **Function**: Use "whether the model can complete inference on the target FPGA within the required time" as a computable metric to guide architecture/bitwidth/sparsity choices.
    - **Mechanism**: Decompose the network into total INT4 MACs, estimate LUT consumption per PE under a LUT-bound deployment strategy, add BRAM (for weight caching) and a few DSPs (for high-precision activations), and align with the available resources of the target chip. Wall-clock inference latency is estimated based on clock frequency and compared to the physical 1 microsecond budget for $d$ rounds.
    - **Design Motivation**: The traditional "train then compress" approach often discovers resource shortages post hoc; this work turns resource estimation into a feedback loop during training, eliminating infeasible solutions at the model selection stage.

### Loss & Training
Binary cross-entropy $\mathcal{L} = -\mathbb{E}_{(s,y)}[y\log f(s) + (1-y)\log(1-f(s))]$; large-scale datasets (up to $10^7$ samples) are used for Stim training; fine-tuning on Sycamore real data for $d=3,5$; INT4 QAT is implemented with Brevitas, initialized from FP32 model parameters to accelerate convergence.

## Key Experimental Results

### Main Results

| Setting | Architecture / Config | Key Results |
|---------|----------------------|-------------|
| $d=9$ surface code, Stim $10^7$ samples | Simple CNN/TCN | Decoding accuracy nearly saturated, significantly better than complex architectures trained on standard datasets |
| MLP | Any scale | Scaling up parameters fails, proving zero inductive bias is infeasible |
| GNN-BP | $d\le9$ | Strongly affected by short cycles, overall lags behind CNN/TCN |
| INT4 PTQ | Most models | "Cliff" observed, logical error rate surges |
| INT4 QAT | Same as above | Nearly recovers FP32 performance, necessary for achieving 1μs latency |

### Ablation Study

| Config | Effect |
|--------|--------|
| Large data + simple CNN | Outperforms "small data + complex architecture" |
| Local convolution + temporal aggregation (CNN+TCN) | Most robust across all scales |
| Transformer w/o convolutional tokenizer | Embedding degrades, accuracy drops significantly |
| GNN (neural BP) | Resolves BP oscillations but still limited by graph topology |
| Pruning only, no quantization | Cannot push inference into LUT-bound region, latency not met |

### Key Findings
- "Increasing data" yields greater decoding gains than "changing architecture" for $d\le9$ surface codes—a conclusion not previously quantified, suggesting industrial QEC efforts should focus more on simulation/real data generation than model innovation.
- Inductive bias is essential: pure MLPs do not scale, GNN-BP suffers from short cycles; only CNN/TCN's "local + temporal" combination is consistently superior.
- INT4 is a hard constraint, not a performance optimization: only QAT can sustain INT4, PTQ almost always fails; microsecond-level real-time decoding requires hardware awareness during training.

## Highlights & Insights
- Incorporating "FPGA resources" as a hard constraint outside the loss function in the pipeline immediately disqualifies seemingly SOTA complex decoders at the engineering level—this "co-design" approach is equally applicable in other latency-critical domains (autonomous driving perception, neural network packet processing).
- The unified re-implementation and comparison of five architectures provides a design checklist for "future QEC neural decoders": inductive bias must include locality + temporality, $\sim 10^5$ parameters suffice, INT4 is the baseline.
- The data-driven finding (simple network + large data > complex network + standard data) is a strong reminder against over-engineering in ML4Science.

## Limitations & Future Work
- Evaluation is limited to $d=9$ (161 physical qubits); inductive bias selection and latency feasibility at higher code distances remain uncharacterized.
- FPGA resource estimation is based on linear MAC decomposition, not accounting for actual power consumption after routing/placement, leaving a gap to production deployment.
- No theoretical lower bound is provided for INT4 training accuracy relative to FP32, leaving "why INT4 suffices" as an open question.

## Related Work & Insights
- **vs AlphaQubit series**: This work serves as an engineering, deployable "stress test" version, comparing transformer blocks under INT4 LUT-bound constraints.
- **vs MWPM/BP**: Traditional decoders remain on the "general-purpose + heuristic" side; this work shows neural decoders can stably outperform with sufficient data, but only compressed models are feasible for real-time use.
- **vs General Model Compression (Gholami et al.)**: This work does not propose new compression algorithms, but strictly combines existing PTQ/QAT/pruning under hardware constraints and validates their boundaries in QEC, providing a template for compression + hardware co-design.
