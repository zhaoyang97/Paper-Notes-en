# Shop-R1: Rewarding LLMs to Simulate Human Behavior in Online Shopping via Reinforcement Learning

## Metadata
- **Conference**: ICLR 2026
- **arXiv**: [2507.17842](https://arxiv.org/abs/2507.17842)
- **Code**: [https://damon-demon.github.io/shop-r1.html](https://damon-demon.github.io/shop-r1.html)
- **Area**: Reinforcement Learning
- **Keywords**: LLM, reinforcement learning, human behavior simulation, online shopping, hierarchical reward, GRPO

## TL;DR
This paper proposes Shop-R1, a framework that leverages hierarchical reward design and difficulty-aware reward scaling within a reinforcement learning paradigm to substantially improve LLMs' ability to simulate realistic human online shopping behavior, achieving over 65% improvement in exact action match compared to SFT baselines.

## Background & Motivation
- LLMs have shown promise in simulating human web navigation behavior, yet existing approaches (zero-shot prompting, SFT) remain unsatisfactory.
- **Zero-shot prompting**: Lacks personalization and adaptability, yielding extremely low accuracy (0.32%).
- **SFT**: Fine-tunes on "rationale–action" training data generated by Claude 3.5 Sonnet, but performance is bounded by the capability ceiling of the model used for rationale generation.
- **Challenges with RL**: Applying RL directly with sparse binary rewards performs poorly (1.01%) and is prone to reward hacking—the model repeatedly predicts the trivial "terminate" action to obtain easy rewards.
- Core problem: How to design RL rewards suitable for behavior simulation (rather than task completion)?

## Method

### Overall Architecture
Shop-R1 formulates human behavior simulation as a two-stage prediction problem:
1. **Rationale Generation**: Given the current web page context and action history, generate a behavioral rationale.
2. **Action Prediction**: Predict the next action (click / type_and_submit / terminate).

### Key Design 1: Format Reward
- Binary reward: the model receives 0.5 if the output format is valid (a JSON object containing both `rationale` and `action` keys), and 0 otherwise.
- Ensures the reliability of downstream reward computation.

### Key Design 2: Self-Certainty Reward
Since ground-truth rationales are unavailable, the model's confidence in its own generated rationale is measured via KL divergence:

$$s(r_t | q_t) = \frac{1}{N|V|} \sum_{j=1}^{N} \sum_{i=1}^{|V|} p_{ij} \log\left(\frac{p_{ij}}{U_i}\right)$$

This represents the average KL divergence between the model's output distribution and a uniform distribution; higher values indicate more certain and consistent rationales.

### Key Design 3: Hierarchical Reward

| Action Type | Type Reward | Sub-action Attribute Reward | Text Similarity Reward |
|---|---|---|---|
| terminate | 0.3 | — | — |
| click | 0.3 | +0.2 (if name ≠ ∅) | +DARS × ROUGE-L(name) |
| type_and_submit | 0.3 | +0.1 (name) + 0.1 (text) | +0.1×ROUGE-L(name) + DARS×ROUGE-L(text) |

### Key Design 4: Difficulty-Aware Reward Scaling (DARS)
- Long-text sub-action attributes (e.g., button labels, search queries) are substantially harder to predict than action types.
- The DARS factor amplifies rewards for correctly predicting these difficult components (default value set to 1000).
- This prevents the model from hacking the reward by repeatedly predicting the simple "terminate" action.

### Loss & Training
The overall RL objective is:

$$\max_{\pi_\theta} \mathbb{E}_{r,a \sim \pi_\theta(q)} \left[ v(a) + \alpha s(r) - \beta \text{KL}(\pi_\theta(r,a|q) \| \pi_{\text{ref}}(r,a|q)) \right]$$

where $v(a)$ denotes the hierarchical action reward, $\alpha=0.005$ controls the weight of the self-certainty signal, and $\beta=0.001$ controls KL regularization.

### Training Pipeline
1. **Cold-start SFT**: Fine-tune on Claude-generated rationale–action data (4 epochs, lr=2e-5).
2. **RL phase**: Policy optimization with GRPO (500 steps, lr=1e-7, batch=64, context length 32K).

## Key Experimental Results

### Main Results: Performance Comparison Across Methods

| Model (Qwen-2.5-3B) | Exact Action Match | Action Type Accuracy | Action Type F1 |
|---|---|---|---|
| Zero-shot | 0.32% | 15.33% | 16.15% |
| RL (Binary) | 1.01% | 6.17% | 9.92% |
| SFT | 16.76% | 22.25% | 24.52% |
| SFT + RL (Binary) | 16.55% | 23.74% | 28.07% |
| **Shop-R1 (Ours)** | **27.72%** | **36.40%** | **31.28%** |

> Shop-R1 achieves over 65% improvement in exact action match over the SFT baseline, while also improving action type and fine-grained matching accuracy.

### Ablation Study: Cross-Model Scale

| Model Scale | SFT | Shop-R1 | Gain |
|---|---|---|---|
| Qwen-2.5-0.5B | 9.90% | **27.72%** | +180% |
| Qwen-2.5-1.5B | 10.86% | **24.11%** | +122% |
| Qwen-2.5-3B | 16.76% | **27.72%** | +65% |

> The hierarchical reward mechanism yields more pronounced gains for smaller models; notably, the 0.5B model achieves performance on par with the 3B model.

### Key Findings
1. Sparse binary RL rewards are insufficient to guide behavior simulation learning and may even cause performance degradation.
2. The hierarchical reward simultaneously improves both coarse-grained (type-level) and fine-grained (exact match) performance.
3. DARS effectively prevents reward hacking, discouraging the model from defaulting to "terminate" predictions.
4. The self-certainty signal provides effective supervision for rationale generation in the absence of ground-truth annotations.
5. The framework generalizes to diverse web page and GUI interaction tasks.

## Highlights & Insights
- **First application of RL to simulation-oriented behavior modeling**, distinct from existing task-completion-focused web agent research.
- **Carefully engineered reward hierarchy**: rewards are structured progressively from format → rationale → action type → sub-action attributes.
- **The DARS mechanism** elegantly addresses the reward hacking problem.
- **0.5B model ≈ 3B model performance**: demonstrates that reward design matters more than model scale.

## Limitations & Future Work
- The task remains confined to a specific e-commerce environment (Shop-CART dataset); generalizability requires further validation.
- Rationale quality is assessed only indirectly via self-certainty, lacking external validation.
- A substantial gap remains between model predictions and real user behavior (27.72% exact match).
- The context length constraint (32K tokens) may result in information loss for long sessions.

## Related Work & Insights
- **LLM behavior simulation**: ReAct (Yao et al., 2023), WebAgent (Gur et al., 2023), UX-Agent (Lu et al., 2025)
- **Reward design**: RLHF (Ouyang et al., 2022), DPO (Rafailov et al., 2023), RLVR/DeepSeek-R1 (Guo et al., 2025)
- **Shopping navigation agents**: WebArena (Zhou et al., 2023), which focuses on task completion rather than behavior simulation
