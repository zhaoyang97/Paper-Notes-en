# Genetic Instruct: Scaling up Synthetic Generation of Coding Instructions for Large Language Models

**Conference**: ACL 2025  
**arXiv**: [2407.21077](https://arxiv.org/abs/2407.21077)  
**Code**: [https://huggingface.co/datasets/nvidia/OpenCodeGeneticInstruct](https://huggingface.co/datasets/nvidia/OpenCodeGeneticInstruct)  
**Area**: LLM/NLP  
**Keywords**: Synthetic data, code generation, evolutionary algorithm, instruction tuning, scalability

## TL;DR
This paper proposes the Genetic-Instruct algorithm, which draws inspiration from the crossover and mutation operations of evolutionary algorithms to scale 512 seed instructions into over 7.5 million high-quality coding instructions. Implementing a three-role pipeline consisting of Instructor-LLM, Coder-LLM, and Judge-LLM, the trained models outperform Self-Instruct and Evol-Instruct on code generation benchmarks.

## Background & Motivation

**Background**: The improvement of LLM code generation capabilities heavily relies on high-quality instruction data, which is expensive to annotate manually. Synthetic instruction generation (e.g., Self-Instruct, Evol-Instruct) serves as an alternative.

**Limitations of Prior Work**: Instructions generated by Self-Instruct are often too simple and lack complexity; Evol-Instruct solely relies on mutation to increase complexity; code-based approaches (such as OSS-Instruct) heavily depend on large-scale, high-quality code repositories.

**Key Challenge**: How to scale a tiny set of seed instructions to millions of diverse and high-quality coding instructions?

**Goal**: To design a highly parallelizable synthetic instruction generation algorithm.

**Key Insight**: Leveraging evolutionary algorithm paradigms—crossover expands topic coverage, mutation increases local diversity, and the fitness function ensures quality.

**Core Idea**: Utilizing crossover, mutation, and selection from evolutionary algorithms, combined with a three-role LLM pipeline (instruction generation, code writing, and quality evaluation), to achieve infinite scalability starting with only 512 seeds.

## Method

### Overall Architecture
Seed instructions (512) -> Evolutionary loop: randomly select crossover or mutation -> Instructor-LLM generates new instructions -> Coder-LLM generates code -> Judge-LLM evaluates quality -> accepted pairs are added to the seed pool -> repeat until the target scale is reached. Multi-colony parallelization + multi-generation iterations.

### Key Designs

1. **Crossover Operation**

    - Self-Instruct style: Select multiple exemplars from the seed pool to perform few-shot generation of new instructions
    - Function: Expand topic coverage
    - Design Motivation: Escape the local topic space of the seed pool

2. **Mutation Operation**

    - Evol-Instruct style: Evolve a single instruction based on predefined rules
    - Function: Increase local diversity and complexity
    - Design Motivation: Enhance difficulty and variation within existing topics

3. **Three-Role LLM Pipeline**

    - Instructor-LLM: Generates instructions
    - Coder-LLM: Generates corresponding code
    - Judge-LLM: Evaluates the quality of instruction-code pairs
    - Design Motivation: Clear division of labor, allowing independent optimization for each role

4. **Multi-Colony Parallelization & Decontamination**

    - Multiple colonies execute the evolutionary loop in parallel
    - Final decontamination ensures no overlap with evaluation benchmarks
    - Design Motivation: Linearly scale up generation speed

## Key Experimental Results

### Main Results -- Code Generation Benchmark Performance (Post-SFT)

| Training Data | HumanEval | MBPP | MultiPL-E | Average |
|---------|-----------|------|-----------|------|
| Self-Instruct | ~60% | ~55% | ~45% | ~53% |
| Evol-Instruct | ~65% | ~58% | ~48% | ~57% |
| OSS-Instruct | ~68% | ~60% | ~50% | ~59% |
| **Genetic-Instruct (7.5M)** | **~75%** | **~67%** | **~58%** | **~67%** |

### Ablation Study -- Data Scale vs. Performance

| Data Scale | HumanEval |
|--------|-----------|
| 100K | ~62% |
| 1M | ~68% |
| 3M | ~72% |
| 7.5M | **~75%** |

### Key Findings
- **7.5M data brings consistent and significant improvements**
- **The coupling of crossover and mutation is critical**: Using either operation in isolation is inferior to combining them
- **Weaker models can still generate effective data**: The strongest LLM is not required to act as the Instructor
- **Fully open-source**: No dependence on closed-source models or proprietary data

## Highlights & Insights
- **The integration of evolutionary algorithms and LLM synthetic data** is highly natural: crossover is responsible for exploration, mutation handles exploitation, and the fitness function guarantees quality
- **The three-role division of labor** is more reliable than single-model generation combined with self-evaluation
- **Scaling from 512 seeds to 7.5 million data points** demonstrates powerful scalability

## Limitations & Future Work
- High computational cost (requires inference from three LLMs)
- Focused solely on coding tasks
- Future directions: Extending to general instructions and adopting adaptive crossover/mutation ratios

## Related Work & Insights
- **vs Self-Instruct**: Self-Instruct only uses crossover, whereas Genetic-Instruct incorporates mutation and quality evaluation
- **vs Evol-Instruct**: Evol-Instruct only uses mutation, lacking the topic expansion provided by crossover
