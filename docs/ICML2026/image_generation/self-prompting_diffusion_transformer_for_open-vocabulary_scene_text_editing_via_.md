# Self-Prompting Diffusion Transformer for Open-Vocabulary Scene Text Editing via In-Context Learning

**Conference**: ICML 2026  
**arXiv**: [2605.15523](https://arxiv.org/abs/2605.15523)  
**Code**: https://hongxiii.github.io/mstedit (Project Page)  
**Area**: Diffusion Models / Image Editing / Scene Text Editing  
**Keywords**: Scene Text Editing, MM-DiT, Self-Prompting, In-Context Learning, Open-Vocabulary

## TL;DR
This paper proposes a self-prompting scene text editing method based on FLUX-Fill (MM-DiT). A style prompt is cropped directly from the source image, and a glyph prompt is rendered using Pillow. These are concatenated with the masked image along the channel dimension and fed into the diffusion backbone. After cooldown training on 4,000 high-quality paired images generated by Nano Banana Pro, the model achieves open-vocabulary text replacement while maintaining style consistency across 13 languages.

## Background & Motivation

**Background**: Current mainstream Scene Text Editing (STE) solutions follow the image inpainting paradigm: the original text area is masked, and a diffusion model regenerates new text within the mask. To ensure correct character structures, methods like AnyText, AnyText2, and GlyphMastero often use a pretrained OCR model as a glyph encoder to extract character-level features.

**Limitations of Prior Work**: This paradigm introduces two specific issues. First, OCR is essentially a classifier with a closed vocabulary, which fails for rare characters, low-resource languages, or artistic fonts. Training a glyph encoder from scratch requires massive amounts of data. Second, inpainting erases visual information in the target area, forcing newly generated text to "borrow" style from surrounding pixels. If the target text style differs from the background (e.g., red "Charmander" surrounded by blue text in Fig. 1), the new text may be incorrectly colored blue, losing the original color, font, and texture.

**Key Challenge**: To preserve the original style of the target text, the model needs to see the pixels in the target area; however, the inpainting setup requires masking that very area. Similarly, to support arbitrary languages/characters, the model cannot rely on closed-vocabulary OCR encoders, yet it must be provided with precise glyph structures.

**Goal**: To enable MM-DiT to achieve both "open-vocabulary glyph correctness" and "consistent style consistency" without introducing additional style or glyph encoders.

**Key Insight**: MM-DiT (specifically FLUX-Fill) possesses inherent multi-modal in-context learning capabilities. Information provided as visual tokens in the input sequence can be utilized naturally within the attention mechanism. The authors propose the "self-prompting" concept: style signals are cropped directly from the original image, and glyph signals are rendered via font libraries, allowing MM-DiT to learn how to use them.

**Core Idea**: Concatenate the style patch cropped from the original image and the glyph map rendered by Pillow with the masked image along the channel dimension. this serves as the "self-prompting" visual input for MM-DiT, replacing specialized OCR or style encoders.

## Method

### Overall Architecture
The backbone is FLUX.1-Fill-Dev (an inpainting-oriented MM-DiT utilizing rectified flow and dual/single-stream transformers). The input consists of three visual signals and two text signals:

- **Visual Path**: A style image $I_s$ cropped from the original image, a glyph image $I_g$ rendered by Pillow, and a masked image $I_m$ with the target area erased. These are concatenated along the channels as $I_{\text{input}}=\mathrm{Concat}(I_g, I_s, I_m)$, and encoded into latent $z_0$ by a frozen VAE encoder.
- **Text Path**: T5 encodes the target text (as a glyph text prompt for semantic structure), and CLIP encodes the style description (as a style text prompt for visual alignment).

The VAE and both text encoders remain frozen, while only the MM-DiT backbone is fine-tuned. Training consists of two stages: 1 epoch of self-supervised pre-training on AnyWord-3M, followed by 10 epochs of cooldown training on 4,000 high-quality pairs generated by Nano Banana Pro. During inference, guidance scale=30 and 30 sampling steps are used, with the output decoded by the VAE and pasted back into the target area.

### Key Designs

1.  **Self-Prompting Visual Input (Style + Glyph Prompt)**:
    - **Function**: Feeds the "original style" and "precise glyph" of the target text into MM-DiT without adding extra encoders.
    - **Mechanism**: The style prompt $I_s$ is taken directly from the original image by cropping the patch corresponding to the mask's bounding box, inherently carrying color, font, texture, and local lighting. The glyph prompt $I_g$ uses Pillow to render the target string into a high-contrast black-and-white single-line map, providing stroke-level geometric priors. Both are concatenated into the VAE. MM-DiT then uses its in-context learning to "copy style from $I_s$, content from $I_g$, and background from $I_m$."
    - **Design Motivation**: Replacing OCR encoders with "rendered maps" makes the vocabulary entirely open (any Unicode character can be edited if the font supports it). Using "original patches" instead of style encoders avoids representation misalignment between encoders and VAE latent space (as seen in TextCtrl) and bypasses the data cost of training style encoders from scratch.

2.  **Cooldown Training and Rectified Flow Objective**:
    - **Function**: Enables the model to upgrade from "rendering text" to "replacing text with style consistency" using only 4,000 paired samples, while preventing the model from simply copying the original text.
    - **Mechanism**: Stage one uses standard rectified flow objective $\mathcal{L}_{\text{RF}}=\mathbb{E}[\|\hat v_\theta(z_t,t,c)-(z_1-z_0)\|_2^2]$ on AnyWord-3M. Stage two draws inspiration from MECO, treating the "original text area" as meta-information in the style prompt and changing the target from "noise → image" to a "source → target" velocity field: let $z_t=(1-\sigma_t)z_0^{\text{src}}+\sigma_t z_0^{\text{tgt}}$, minimizing $\mathcal{L}_{\text{CD}}=\mathbb{E}[\|\hat v_\theta(z_t,t,c)-(z_0^{\text{tgt}}-z_0^{\text{src}})\|_2^2]$.
    - **Design Motivation**: Training directly with the original image can lead to collapse where the model lazily copies both style and glyphs, causing editing failure. Predicting the "source-to-target differential velocity field" explicitly tells the model what to change and what to keep, decoupling style preservation and content replacement during optimization.

3.  **Paired Data Construction (Nano Banana Pro + Manual Filtering)**:
    - **Function**: Obtains the "original image + style-consistent edited image" pairs required for cooldown training at low cost, addressing the deficiency in datasets like AnyWord-3M where original text is often already erased.
    - **Mechanism**: Use the instruction-based editing model Nano Banana Pro to generate candidate pairs, followed by manual filtering based on three criteria: (a) non-target regions remain unchanged; (b) generated text is semantically correct; (c) edited text maintains consistent color, font, and texture. 4,000 pairs were retained.
    - **Design Motivation**: Real-world style-consistent pairs are nearly non-existent, but cooldown training requires "two images identical except for the text" to learn style retention. Using a strong generative model as a synthesizer and humans as filters is a cost-effective compromise.

### Loss & Training
Two stages: (1) 1 epoch of standard rectified flow objective $\mathcal{L}_{\text{RF}}$ on AnyWord-3M; (2) 10 epochs of cooldown objective $\mathcal{L}_{\text{CD}}$ on 4,000 pairs. Optimizer: AdamW, constant lr=$2\times10^{-5}$, bf16 + 8-bit optimizer state, per-GPU batch=1 with grad-accum 8 (effective batch 64), 8×A100. Multi-lingual data is mixed for training without language-level scheduling.

## Key Experimental Results

### Main Results
Comparison with 7 SOTAs on AnyText-benchmark (1,000 test images each for English/Chinese):

| Dataset | Metric | Ours | Prev. SOTA (TextFlux) | Gain |
| :--- | :--- | :--- | :--- | :--- |
| English | Sen.ACC ↑ | 0.8857 | 0.8231 | +6.26 pt |
| English | NED ↑ | 0.9568 | 0.9235 | +3.33 pt |
| English | FID ↓ | 7.62 | 13.42 | -43% |
| English | LPIPS ↓ | 0.0365 | 0.0721 | -49% |
| Chinese | Sen.ACC ↑ | 0.8249 | 0.7289 | +9.60 pt |
| Chinese | NED ↑ | 0.9147 | 0.8612 | +5.35 pt |
| Chinese | FID ↓ | 7.95 | 13.67 | -42% |
| Chinese | LPIPS ↓ | 0.0268 | 0.0524 | -49% |

On the self-built MST-Edit multi-lingual dataset (covering 11 languages such as Arabic, French, German, Korean, Japanese, etc.), our method significantly outperforms OCR-free baselines (FluxText, TextFlux). Latin-based languages perform best due to similar stroke structures, while Thai performs slightly lower due to complex glyph layouts.

### Key Findings
- Benefits of style prompt + cooldown are mainly reflected in image quality (FID/LPIPS reduced by ~40%), while text accuracy improvements are more modest (+1 pt), indicating this design primarily "fixes style" rather than "fixing glyphs."
- Stroke-level rather than character-level representation leads to positive multi-lingual transfer: as new languages were added in a sequence, Seq.ACC for previously learned languages did not drop but rose steadily.
- Qualitative results (Fig 6) show that without style prompts, the model renders fonts never present in the original image or destroys the background; the full model preserves both.

## Highlights & Insights
- **"Self-Prompting" is a direct physicalization of in-context learning**: Instead of training encoders to map info into tokens, feeding original patches and rendered images as tokens allows MM-DiT's attention to select what is needed. This approach is applicable to other local editing tasks requiring style/content decoupling (logo replacement, sticker editing).
- **Using general-purpose editing models as "Data Synthesizers"**: 4,000 high-quality pairs via Nano Banana Pro + manual filtering is orders of magnitude cheaper than collecting real pairs, offering a general paradigm for low-resource tasks.
- **The $z_0^{\text{tgt}}-z_0^{\text{src}}$ differential velocity field target is clever**: It explicitly instructs the model to only predict the change, naturally preventing collapse. This trick can be transferred to other diffusion tasks requiring local editing with global preservation.

## Limitations & Future Work
- Glyph prompts depend on Pillow and font files. If a character is missing from the font file, rendering fails—limiting "openness" to the font library's coverage.
- Style prompts come from the bounding box of the mask. If the mask includes significant background or multiple fonts, the patch may introduce irrelevant styles or drift.
- Cooldown data is limited to 4,000 pairs from a single generator (Nano Banana Pro), potentially distilling generator biases. Future work could mix multiple generators and use auto-scoring filters.
- High computational cost: Full-parameter tuning of FLUX-Fill with guidance=30 and 30 steps makes deployment more expensive than LoRA-based STE solutions. Distillation into a lighter student model would be more practical.

## Related Work & Insights
- **vs AnyText/AnyText2 (Tuo 2023/2024)**: They use OCR encoders for character-level features; this work uses rendered glyph maps for stroke-level features. This work offers open-vocabulary support and 13 languages, though limited by font libraries.
- **vs FluxText / TextFlux (2025)**: Also OCR-free, but they render glyphs directly inside the mask. This work adds "original patches as style prompts + cooldown" which leads to a 40%+ gap in FID/LPIPS.
- **vs TextCtrl (Zeng 2024)**: TextCtrl uses a specialized style encoder, which suffers from space misalignment. This work places style signals directly in the VAE input channels for natural alignment.
