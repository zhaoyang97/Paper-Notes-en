# TokenTiming: A Dynamic Alignment Method for Universal Speculative Decoding Model Pairs

**Conference**: ACL2026  
**arXiv**: [2510.15545](https://arxiv.org/abs/2510.15545)  
**Code**: TBD  
**Area**: time_series / LLM inference acceleration  
**Keywords**: Speculative decoding, heterogeneous vocabularies, Dynamic Time Warping, inference acceleration, probability mapping

## TL;DR
TokenTiming re-encodes token sequences generated by a draft model into the target tokenizer space and constructs many-to-many token alignment using Dynamic Time Warping. This allows off-the-shelf small models with heterogeneous vocabularies to serve as speculative decoding draft models, achieving up to 1.57x acceleration across multiple 14B-70B target models.

## Background & Motivation
**Background**: Speculative decoding has become a practical class of methods for LLM inference acceleration. A small draft model first rapidly proposes multiple candidate tokens, and a large target model verifies these candidates in a single parallel forward pass. If the candidate distribution is sufficiently close to the target distribution, the number of target model calls can be reduced without changing the final generation distribution.

**Limitations of Prior Work**: Standard speculative decoding assumes that the draft and target models share the same vocabulary; otherwise, draft token probabilities cannot be directly used for accept-reject sampling against target token probabilities. In practice, this is highly restrictive as many strong models utilize independent tokenizers. Even within the same model family, smaller versions might still be too large to provide sufficient acceleration gains. Alternatively, retraining Medusa/EAGLE-style draft heads for each target model incurs significant training and model-switching costs.

**Key Challenge**: The "lossless" nature of speculative decoding relies on strict calibration at the probability distribution level, but heterogeneous tokenizers split the same string into tokens of different granularities. Existing TLI only transfers probabilities over the intersection of vocabularies, which easily degrades to incomplete calibration when encountering tokens outside the intersection. SLEM supports string matching but cannot facilitate probability sampling. In other words, there is a direct conflict between universality and lossless verification.

**Goal**: The authors aim to allow any off-the-shelf small model to serve as a draft model without retraining, model modification, or shared vocabulary requirements. Meanwhile, the method must preserve the distribution consistency of speculative sampling and ensure that the additional alignment overhead is low enough to not offset acceleration gains.

**Key Insight**: The paper observes that the problem of heterogeneous tokenizers is essentially sequence alignment across two "timelines": the draft token sequence and the proxy token sequence obtained after re-tokenizing the string by the target tokenizer. These sequences differ in length and local granularity but describe the same string. Dynamic Time Warping (DTW) is particularly adept at finding monotonic, many-to-many minimum cost paths between sequences of different lengths.

**Core Idea**: Use DTW to establish a dynamic alignment path between draft tokens and target proxy tokens, then transfer draft probabilities to target tokens along this path to execute standard speculative sampling with the mapped probabilities.

## Method

### Overall Architecture
TokenTiming is a pure inference-time algorithm. In each decoding round, starting from the current prefix, the draft model first generates a draft token sequence of length $k$. The system decodes these draft tokens into a string and then re-tokenizes it using the target tokenizer to obtain a proxy target token sequence. Due to different tokenizers, the draft sequence length $k$ and proxy sequence length $m$ are usually different, and local token boundaries are misaligned.

Subsequently, TokenTiming runs Dynamic Token Warping on these two sequences to obtain a monotonic alignment path. Nodes in the path can represent one-to-one, one-to-many, or many-to-one relationships, covering cases where "Scaling" is a single token in one tokenizer but multiple sub-tokens in another. Finally, the algorithm maps the probabilities from the draft side to the proxy target tokens based on this path. The target model performs a parallel forward pass on the proxy sequence, accepting or rejecting tokens one by one according to standard speculative sampling rules. Upon rejection, a compensation token is sampled from the target distribution to update the prefix.

### Key Designs
1. **Dynamic Token Warping Alignment**:
    - **Function**: Construct a complete many-to-many mapping between the draft token sequence and the target proxy token sequence to resolve inconsistencies in token granularity and positioning under heterogeneous tokenizers.
    - **Mechanism**: The algorithm constructs a cumulative cost matrix $C$, with Levenshtein edit distance used as the local distance metric. Each position selects the minimum cumulative cost from the top, left, or top-left neighbors, and the optimal path $\pi^*$ is obtained via backtracking from the endpoint. This path is not a simple vocabulary intersection match but a dynamic alignment determined jointly by string similarity and sequence order.
    - **Design Motivation**: Misalignments in heterogeneous tokenizers are typically local and monotonic rather than completely disordered. DTW accommodates local stretching or compression while maintaining order, making it more suitable than TLI (which only checks for identical tokens) for handling granularity differences in BPE or WordPiece.

2. **Probability Transfer with Window Constraints**:
    - **Function**: Convert candidate probabilities from the draft side into candidate probabilities for target proxy tokens, enabling the use of standard speculative sampling formulas.
    - **Mechanism**: The alignment path provides correspondences between draft token blocks and target token blocks. TokenTiming distributes probabilities along this path. During target-side verification, $\min(1, q(t_j) / p(t_j))$ is still used as the acceptance probability, where $q$ comes from the target model and $p$ from the mapped draft distribution. To reduce DTW computation, the authors introduce a Sakoe-Chiba Band, searching only within a diagonal region where $|i-j| \leq w$, reducing complexity from $O(km)$ to $O(w\max(k,m))$.
    - **Design Motivation**: The key to lossless speculative decoding is not just making the token strings look identical, but providing a reasonable draft probability for accept-reject calibration. The window constraint exploits the fact that tokenization misalignment usually does not drift infinitely, exchanging minimal alignment overhead for more stable probability mapping.

3. **Plug-and-play Heterogeneous Draft Model Usage**:
    - **Function**: Allow any off-the-shelf small model to serve as a draft model without retraining draft heads or aligning vocabularies.
    - **Mechanism**: TokenTiming handles tokenizer differences within a lightweight alignment step between each Draft-Verify round. Neither the target model nor the draft model requires weight modifications. In experiments, draft models ranging from 68M Vicuna to 350M OPT and 0.5B/0.6B Qwen were utilized, while target models spanned dense, distilled, and MoE architectures.
    - **Design Motivation**: The real hurdle for speculative decoding deployment is not the algorithmic form but "finding a small draft model with the same vocabulary for every target." If heterogeneous vocabularies are no longer a hard constraint, systems can prioritize draft models based on speed, capability, and deployment conditions.

### Loss & Training
TokenTiming involves no model training and introduces no new parameters. It only adds three steps during inference: re-tokenization, DTW alignment, and probability mapping. Experiments compared different window widths $w=4, 8, 16, \infty$, finding that an appropriate local window (e.g., $w=8$) is more beneficial than unconstrained alignment as it reduces overhead and prevents probability mapping from being distorted by tokens at distant positions. The paper reports that the overhead per round for TokenTiming is approximately 663 microseconds, accounting for 0.1%-0.5% of the total runtime, which is far less than the gains from throughput improvement.

## Key Experimental Results

### Main Results
The authors evaluated 25 target/draft model combinations on Spec-Bench, covering tasks such as Mathematics, Code, Translation, Summarization, and QA. The table below extracts representative combinations, showing TPS, acceptance rate, and speedup relative to AR from Table 1 of the paper.

| Target Model | Draft Model | TLI TPS | TokenTiming TPS | TLI Accept Rate | TokenTiming Accept Rate | TLI Speedup | TokenTiming Speedup |
|----------|------------|---------|-----------------|------------|--------------------|----------|------------------|
| DeepSeek-R1-Distill-Llama-70B | Qwen2.5-0.5B | 15.68 | 19.26 | 0.34 | 0.40 | 1.07x | 1.31x |
| DeepSeek-R1-Distill-Llama-70B | OPT-350M | 16.03 | 21.35 | 0.19 | 0.31 | 1.09x | 1.45x |
| Qwen3-32B | Qwen3-0.6B | 19.16 | 24.78 | 0.43 | 0.42 | 1.21x | 1.57x |
| Phi-4 | Qwen2.5-0.5B | 17.64 | 35.58 | 0.19 | 0.39 | 0.76x | 1.54x |

These results indicate that TokenTiming's gains are not limited to a specific model family. On OPT/Vicuna drafts with low vocabulary overlap, it still provides usable acceleration. On target models like Qwen3-32B and Phi-4, DTW alignment significantly expands the token probability space that TLI originally could not exploit.

### Ablation Study
The paper compared the speedup of TLI vs. TokenTiming by task category. The following table highlights representative results, demonstrating the stability of the method across different generation tasks.

|--------------|---------------|---------------|---------------|---------------|-------------|

| Qwen3-32B / Qwen2.5-0.5B | 1.44x→2.53x | 1.29x→1.80x | 1.91x→2.49x | 1.41x→1.28x | 1.01x→1.13x |

Another significant analysis is the performance gap compared to same-vocabulary SOTA: On a 7B target, EAGLE-3 reaches 2.58x, while TLI peaks at ~1.32x; TokenTiming-OPT-350M improves this to 1.80x. On a 33B target, TokenTiming-OPT-350M reaches 2.27x, surpassing Medusa's 1.71x and EAGLE-1's 2.21x, trailing EAGLE-3's 2.71x by only 0.44x.

### Key Findings
- The value of DTW is most evident in heterogeneous vocabulary scenarios: when vocabulary intersection is insufficient to cover draft output, TLI loses many calibratable probabilities, whereas TokenTiming persists in establishing usable mappings along the string sequence.
- Window constraints are not purely for saving time. The paper finds $w=8$ is superior to unconstrained alignment, suggesting that overly wide alignment introduces unstable mappings between distant tokens.
- The method needs to account for inflated speeds caused by repetitive generation. The authors filtered out approximately 15% of pathological repetitive samples from the main analysis to prevent "easily predictable repeated tokens" from artificially boosting acceptance rates and speedups.

## Highlights & Insights
- Reformulating tokenizer mismatch as sequence timeline alignment is highly ingenious. It bypasses the discrete "vocabulary intersection" constraint and leverages the monotonic structure at the string level, providing a continuous bridge for probability transfer.
- The engineering posture of the method is very practical: no training, no model changes, and no binding to the same model family, performing only lightweight alignment during inference. For real-world inference services, this is easier to deploy than maintaining dedicated draft heads for every target model.
- The paper's handling of the "lossless" problem is more rigorous than simple string matching. TokenTiming does not just generate identical-looking text; it reintegrates the mapped draft probabilities into standard speculative sampling rules to preserve target model distribution consistency as much as possible.

## Limitations & Future Work
- The paper acknowledges that the current probability transfer is close to one-hot, primarily transferring top-1 token probabilities directly, without fully utilizing the probability mass of more candidate tokens in the draft distribution.
- The DTW distance is based on character/edit distance rather than semantic distance. For mixed Chinese-English text, special Unicode symbols, or morphologically rich languages, character similarity may not equate to reasonable token probability correspondence.
- While the experiments cover various tasks and models, they primarily evaluate offline benchmarks. System factors in real services, such as batch scheduling, KV cache management, and multi-user tail latency, require further verification.
- Future work could explore semantic-aware or tokenizer-aware distance functions, or extend probability allocation from "direct assignment on path" to local soft alignment to further reduce mismatch risks.

## Related Work & Insights
- **vs TLI**: TLI transfers probabilities over the draft/target vocabulary intersection. It is simple, but handling of tokens outside the intersection is incomplete. TokenTiming uses DTW to construct full token paths and can thus handle draft models with very small vocabulary intersections.
- **vs RDK**: RDK redistributes draft distributions to target distributions via matrices, an approach closer to global vocabulary mapping. TokenTiming focuses on online sequence alignment dependent on the currently generated string, requiring no pre-learned transformation matrices.
- **vs Medusa / EAGLE**: Medusa and EAGLE achieve strong acceleration through additional draft heads or specialized training but are typically tied to the target model. TokenTiming still has an acceleration gap but offers cross-model plug-and-play capability.

## Rating
- **Novelty**: ⭐⭐⭐⭐☆ Using DTW to solve speculative decoding for heterogeneous tokenizers is natural but elegantly framed. The core contribution lies in the problem reformulation and the implementation of probability mapping.
- **Experimental Thoroughness**: ⭐⭐⭐⭐☆ Model combinations, task types, and window analysis are comprehensive, though evaluation in real-world serving scenarios could be strengthened.
- **Writing Quality**: ⭐⭐⭐⭐☆ The main narrative is clear and illustrations are intuitive; some table layouts and probability mapping details could be more refined.
- **Value**: ⭐⭐⭐⭐⭐ Heterogeneous draft models are a key bottleneck for speculative decoding deployment; this paper provides a low-cost, practical path toward universal application.
