# MindForge: Empowering Embodied Agents with Theory of Mind for Lifelong Cultural Learning

**Conference**: NeurIPS 2025
**arXiv**: [2411.12977](https://arxiv.org/abs/2411.12977)
**Code**: [https://github.com/tapri-lab/mindforge](https://github.com/tapri-lab/mindforge)
**Area**: LLM Agent / Embodied Intelligence
**Keywords**: Theory of Mind, Cultural Learning, Multi-Agent Collaboration, Minecraft, Knowledge Distillation

## TL;DR
MindForge introduces explicit Theory of Mind (ToM) representations, natural language communication, and a multi-component memory system into LLM-driven embodied agents, enabling open-source LLM agents to substantially improve task completion rates through collaborative dialogue with expert agents (without gradient updates), achieving 3× more tech-tree milestones and 2.3× more unique items than Voyager in Minecraft.

## Background & Motivation

**State of the Field**: LLM-based lifelong learning agents such as Voyager have demonstrated continuous exploration and skill acquisition in Minecraft, but rely heavily on GPT-4's code generation capabilities.

**Limitations of Prior Work**: When GPT-4 is replaced with open-source LLMs (Mistral-7B, Llama 3.1-8B), Voyager fails even at the most basic tasks such as collecting dirt (success rate of only 4–7%). Existing agents learn in isolation, overlooking the central role of social learning in human intelligence. PEFT fine-tuning is also ineffective—fine-tuning Mistral-7B on GPT-4 execution trajectories yields virtually no improvement in success rate.

**Root Cause**: Open-source LLMs have insufficient code generation and commonsense reasoning capabilities, yet direct fine-tuning fails to effectively transfer structured knowledge. There is no mechanism to improve weaker models through interaction without gradient updates.

**Paper Goals**: Enable capability-limited open-source LLM agents to improve through social interaction (dialogue with experts), and verify whether weak-weak collaboration can also produce emergent improvements.

**Starting Point**: Drawing on cultural learning theory from developmental psychology—humans internalize skills by observing others' perspectives and inferring others' beliefs and intentions—the paper models this as explicit ToM reasoning plus natural language dialogue between agents.

**Core Idea**: Equip agents with explicit ToM representations via BDI (Belief-Desire-Intention) causal templates, and implement social knowledge distillation through natural language dialogue, bridging the capability gap between open-source LLMs and GPT-4 without any gradient updates.

## Method

### Overall Architecture
MindForge augments Voyager with three components: (1) structured BDI representations based on BigToM causal templates, linking perception–belief–desire–action; (2) a natural language communication interface built on Minecraft's chat system; and (3) a Soar cognitive architecture-style memory system comprising episodic, semantic, and procedural memory. Upon task failure, an agent initiates communication, and the expert provides targeted feedback by inferring the partner's mental state.

### Key Designs

1. **Structured ToM Representation (BDI + BigToM)**:

    - **Function**: Maintains structured mental state representations for each agent regarding both itself and its partner.
    - **Mechanism**: Beliefs are categorized into four types—perception-related (from the Minecraft API), task-related (understanding of goals), interaction-related (extracted from dialogue), and partner-related (inference about the partner's mental state). Each belief type is generated by a separate LLM call, forming a causal graph structure.
    - **Design Motivation**: Unstructured ToM performs poorly on complex tasks (confirmed by ablation study, Table 8). Structured representations enable experts to precisely diagnose a novice's false beliefs (e.g., "digging dirt requires a tool") and provide targeted corrections.

2. **Natural Language Communication + Perspective-Taking**:

    - **Function**: Upon task failure, agents communicate with partners via in-game chat; the expert provides assistance by reasoning over the partner's mental model.
    - **Mechanism**: The expert uses its internally maintained BigToM graph of the partner to simulate what the partner knows, believes, and needs, and explicitly considers the partner's perspective when generating responses. Partner beliefs are continuously updated as dialogue progresses.
    - **Design Motivation**: Addresses two primary failure modes: (a) false beliefs (e.g., not knowing that dirt requires no tool) → corrected directly through dialogue; (b) code generation errors (e.g., misuse of the Mineflayer API) → expert provides correct usage. Perspective-taking makes feedback more targeted.

3. **Three-Component Memory System**:

    - **Function**: Episodic memory stores past failure experiences and social interactions; semantic memory stores general task/environment knowledge; procedural memory (skill library) stores reusable code.
    - **Mechanism**: Episodic memory retrieves historical failure scenarios similar to the current task, preventing repeated mistakes. Semantic memory abstracts general knowledge from episodes (e.g., "mining iron ore requires a stone pickaxe"). The three memory types jointly influence belief updates and action generation.
    - **Design Motivation**: Ablation experiments show that removing episodic memory reduces success rate (Table 9), validating the value of reusing failure experience.

### Loss & Training
- No gradient updates; purely inference-time optimization (test-time compute scaling).
- Communication protocol: dialogue is triggered upon task failure, with action and communication rounds alternating.
- Default of 4 action opportunities, with communication rounds interspersed.

## Key Experimental Results

### Main Results

| Setting | Model | Dirt Collection Success Rate | Wood Collection Success Rate |
|---------|-------|-----------------------------|-----------------------------|
| Voyager (solo) | GPT-4 | 100% | 100% |
| Voyager (solo) | Mistral-7B | 7% | 4% |
| Voyager (solo) | Mixtral-8x7B | 27% | 27% |
| Voyager + PEFT | Mistral-7B | 7% | 12.5% |
| MindForge (no interaction) | Mistral-7B | 37.5% | 33.3% |
| MindForge + GPT-4 expert | Mistral-7B | +16.16% | +12.52% |
| MindForge + GPT-4 expert | Mixtral-8x7B | +37.51% | +20.8% |
| MindForge + human expert | Avg. across models | +57.85% | — |

### Key Findings
- Open-source LLMs achieve substantial success rate improvements through MindForge collaboration (Mixtral: dirt collection 27% → 66.6%), though they still cannot fully match GPT-4.
- Performance improves with more communication rounds—dirt collection success rises from ~30% to ~70% as rounds increase.
- Weak-weak collaboration (two Mixtral agents) alone performs poorly, but after one round of GPT-4 guidance followed by mutual collaboration, group success rate rises from 62% to 79%, exhibiting a Condorcet jury effect.
- The perspective-taking module contributes up to 13% improvement in success rate (ablation, Table 7).
- Knowledge acquired through collaboration transfers to out-of-distribution tasks (generalization verified).

## Highlights & Insights
- **Social distillation as an alternative to gradient distillation**: Transferring structured knowledge through dialogue is more effective than PEFT fine-tuning on GPT-4 trajectories (fine-tuning yields almost no improvement, while dialogue achieves 40%+ gains). This is fundamentally a form of test-time compute scaling.
- **Condorcet effect emerges among weak agents**: Two capability-limited agents can achieve group-level improvement through multi-round dialogue, suggesting that social interaction itself constitutes a form of computational resource.
- **Structure of ToM matters**: Structured BDI representations outperform unstructured natural language descriptions on complex tasks, as the causal graph structure enables more precise reasoning.

## Limitations & Future Work
- The Minecraft environment is relatively simple; the approach has not been validated on more complex real-world embodied tasks.
- Even with collaboration, small open-source models (7B/8B) still fall significantly short of GPT-4 running alone.
- Increased communication rounds introduce latency, which may be impractical for real-time tasks.
- Partner modeling relies on LLM inference, which may produce second-order false beliefs.

## Related Work & Insights
- **vs. Voyager**: Voyager learns in isolation and improves only through self-reflection; MindForge adds a social interaction dimension, which is particularly effective for open-source LLMs.
- **vs. CoELA/COMBO**: CoELA supports multi-agent communication but lacks explicit ToM reasoning and belief representations; MindForge's structured perspective-taking is more precise.
- **vs. Knowledge Distillation**: Traditional distillation transfers knowledge via logits or weights; MindForge achieves this through natural language dialogue without requiring access to model internals.
