# When to Retrain after Drift: A Data-Only Test of Post-Drift Data Size Sufficiency

**Conference**: ICLR 2026
**arXiv**: [2603.09024](https://arxiv.org/abs/2603.09024)
**Code**: Not mentioned
**Area**: Other / Streaming Data Learning
**Keywords**: Concept drift, retraining timing, data sufficiency, streaming learning, weighted local regression, state dependence

## TL;DR
CALIPER proposes a detector- and model-agnostic, data-only test that estimates the minimum amount of post-drift data required for safe retraining after abrupt concept drift. It tracks the monotonic non-increasing trend of a surrogate error from weighted local regression (WLR) as the locality parameter $\theta$ increases, combined with an effective sample size (ESS) gate, without requiring any actual retraining of the downstream model.

## Background & Motivation

**Background**: Maintaining predictor performance on non-stationary data streams requires rapid adaptation to concept drift. Window-based detectors such as ADWIN and KSWIN can detect whether and when drift has occurred, but cannot indicate how much post-drift data is sufficient to safely retrain.

**Limitations of Prior Work**: (1) The gap between detection and retraining — drift detectors signal "a change has occurred" but not "enough data has been collected." (2) Premature retraining (insufficient data) leads to overfitting and oscillation. (3) Delayed retraining (waiting too long) keeps a stale model in deployment, causing sustained performance degradation. (4) Repeatedly attempting to retrain deep networks to assess readiness is computationally prohibitive in streaming settings.

**Key Challenge**: How can one determine, purely from data and without accessing model internals or performing actual retraining, whether the post-drift window is sufficiently large?

**Goal**: Design a model-agnostic stopping criterion $R(\mathbf{X}_t) \in \{0,1\}$ that uses purely data-side signals to identify the earliest safe retraining moment.

**Key Insight**: Exploiting **state dependence** in data streams generated by dynamical systems — nearby states exhibit similar one-step transitions — such that a post-drift window with sufficient local consistency can be deemed safe for retraining.

**Core Idea**: A single-pass weighted local regression tracks the monotonic non-increasing trend of surrogate error as the locality parameter $\theta$ increases, gated by an ESS check, to determine data sufficiency without retraining the model.

## Method

### Overall Architecture
CALIPER executes a four-step pipeline after a drift alarm: (1) window normalization and segmentation; (2) effective sample size (ESS) check; (3) weighted local regression (WLR); (4) monotonicity test and trigger. All operations require only a single pass and no access to model internals.

### Key Designs

1. **Window Normalization and Segmentation**:

    - Function: Transforms the post-drift window into a reference set and query pairs.
    - Mechanism: The normalized post-drift window $\mathbf{Z} \in \mathbb{R}^{n_t \times d}$ is split into reference pairs $(\mathbf{X}_h, \mathbf{Y}_h)$ (consecutive state-transition pairs) and a current query $(\mathbf{x}_q, \mathbf{y}_q)$.
    - Design Motivation: Exploits the one-step transition structure $\mathbf{x}(t+1) = f(\mathbf{x}(t)) + \xi_t$ of dynamical systems for self-supervised prediction.

2. **ESS Gating Mechanism**:

    - Function: Checks whether the effective sample size under the tightest locality is sufficient.
    - Mechanism: Kernel weights are $w_i(\theta) = \exp(-\theta r_i)$, and the effective sample size is $\text{ESS}(\theta_{\max}) = \frac{(\sum_i w_i)^2}{\sum_i w_i^2}$. Execution continues only if $\text{ESS}(\theta_{\max}) \geq C(d+1)$.
    - Design Motivation: Since ESS is monotonically non-increasing in $\theta$, checking at $\theta_{\max}$ alone guarantees sufficiency at all $\theta$ values.

3. **Weighted Local Regression and Surrogate Error**:

    - Function: Fits lightweight regression models under varying locality.
    - Mechanism: For each $\theta \in \Theta$, the weighted normal equations $\boldsymbol{\beta}_\theta = \mathbf{A}_\theta^{-1}\mathbf{B}_\theta$ are solved, the surrogate error $e_{(t,\theta)} = \|\mathbf{y}_q - \hat{\mathbf{y}}_\theta\|$ is computed, and accumulated as $E_{(t,\theta)} = E_{(t-1,\theta)} + e_{(t,\theta)}$.
    - Design Motivation: Smaller $\theta$ yields a more global average, while larger $\theta$ focuses on closer neighbors. Under state dependence, increasing $\theta$ should reduce error.

4. **Monotonicity Test and Trigger**:

    - Function: Detects whether the cumulative surrogate error is monotonically non-increasing as $\theta$ increases.
    - Mechanism: The condition $E_{(t,\theta_k)} \geq E_{(t,\theta_{k+1})}\ \forall k$ is tested over the ordered grid $\Theta = \{\theta_k\}$. If satisfied, $R(\mathbf{X}_t) = 1$ and retraining is triggered.
    - Design Motivation: Monotonicity indicates that the data exhibits sufficient state dependence and local regularity for safe retraining.

### Loss & Training
CALIPER itself requires no training. Theoretical analysis shows that windows passing the CALIPER monotonicity test exhibit stronger state dependence than those that do not (Proposition 1), and stronger state dependence is associated with tighter generalization bounds (interpreted via data-dependent generalization bounds). The algorithm has time complexity $O(d^2 K)$ per update (where $K$ is the size of the locality grid) and memory complexity $O(d^2)$.

|---------------|-------------|

### Key Findings
- CALIPER is effective across different learner families (KRR, MLP, Transformer), confirming model-agnosticism.
- CALIPER is effective under both ADWIN and KSWIN detectors, confirming detector-agnosticism.
- Performance degrades at excessively large data sizes (due to delayed use of a stale model), demonstrating that "more data is not always better."
- The data sizes selected by CALIPER are generally close to the posterior optimal point (i.e., the point of lowest error).
- Computational overhead is negligible (microseconds per step).

## Highlights & Insights
- **Value of problem formulation**: Formalizing "when to retrain after drift" as an independent problem fills the gap between drift detection and model adaptation — a practically critical yet nearly unstudied question.
- **State dependence insight**: Recasting data sufficiency as detection of monotonicity in local regression provides an elegant and practical self-supervised indicator.
- **Theory–practice alignment**: Proposition 1 provides a formal link between the monotonicity test and state dependence, while the data-dependent generalization bound interpretation offers theoretical grounding for the algorithm.
- **Minimal overhead**: CALIPER performs only small-scale weighted regression with no model retraining cost.

## Limitations & Future Work
- Assumes data are generated by a dynamical system $\mathbf{x}(t+1) = f(\mathbf{x}(t)) + \xi_t$; may not apply to non-temporal or non-state-dependent data.
- The choice of locality grid $\Theta$ (though claimed to require no tuning) may affect detection sensitivity for different types of drift.
- Only abrupt drift is addressed; gradual drift scenarios require alternative methods.
- The ESS gating constant $C$ may need to be adjusted based on problem dimensionality.
- Theoretical analysis imposes certain restrictions on mixing conditions and noise assumptions.

## Related Work & Insights
- **vs. ADWIN/KSWIN**: These methods only detect whether drift has occurred; CALIPER determines when data are sufficient. The two are complementary — detectors raise the alarm, and CALIPER decides when to retrain.
- **vs. Incremental learning (FSNet/OneNet, etc.)**: Incremental methods attempt continuous adaptation but underperform full retraining under abrupt drift. CALIPER provides the signal for when full retraining should be triggered.
- **vs. D-Tracker/RegimeCast**: These handle regime transitions but similarly do not address the retraining data size problem.
