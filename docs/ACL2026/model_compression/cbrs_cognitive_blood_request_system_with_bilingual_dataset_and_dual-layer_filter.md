# CBRS: Cognitive Blood Request System with Bilingual Dataset and Dual-Layer Filtering

**Conference**: ACL 2026 Findings  
**arXiv**: [2604.16665](https://arxiv.org/abs/2604.16665)  
**Code**: [GitHub](https://github.com/aaniksahaa/CBRS)  
**Area**: Model Compression  
**Keywords**: Blood Request Detection, Bilingual Dataset, Dual-Layer Filtering, Low-Resource Languages, Information Extraction

## TL;DR
CBRS proposes a multi-platform framework that efficiently detects and parses blood donation requests from social media streams via a dual-layer filtering architecture (lightweight classifier + LLM). It constructs the first dataset of 11K Bengali-English-Transliterated Bengali blood donation requests, where a LoRA-fine-tuned Llama-3.2-3B achieves 92% zero-shot accuracy in parsing tasks.

## Background & Motivation

**Background**: Urgent blood donation requests on social media are often buried under massive daily messages. Traditional app-based systems rely on manual input and struggle to reach users in low-resource environments. Existing disaster information extraction research primarily focuses on English and high-resource languages.

**Limitations of Prior Work**: (1) The volume of messages is enormous, but the proportion of blood requests is extremely low, necessitating efficient filtering; (2) Pure LLM filtering is unscalable due to high inference costs, while pure lightweight models suffer from high miss rates; (3) Detection alone is insufficient, as structured information (blood group, hospital, contacts, etc.) must be extracted from free-form text; (4) There is a lack of relevant datasets for the Bengali language.

**Key Challenge**: In blood request detection, the cost of a false negative is significantly higher than a false positive, yet pursuing high recall increases the downstream processing burden.

**Goal**: To build a cost-effective, multilingual, and multi-platform system for blood donation request detection and parsing.

**Key Insight**: Decouple the objectives of "high-recall filtering" and "high-precision verification + parsing" using a dual-layer architecture.

**Core Idea**: The first layer uses an asymmetrically weighted lightweight classifier to ensure high recall, while the second layer utilizes an LLM to simultaneously perform precise filtering and structured parsing, sharing a single API call.

## Method

### Overall Architecture
Original messages → Layer 1 (TF-IDF + Asymmetric Weighted Logistic Regression) for rapid coarse filtering → Layer 2 (GPT-4o-mini) for precise filtering + structured parsing → Output JSON structured requests → Location-based donor notification system.

### Key Designs

1.  **Dual-Layer Filtering (DLF)**:
    - **Function**: Achieves high-recall blood request detection under high throughput.
    - **Mechanism**: Layer 1 uses subword tokenization + TF-IDF features + asymmetric weighted binary cross-entropy ($\alpha=12$ to penalize false negatives) to ensure extremely high recall. Layer 2 employs GPT-4o-mini for precise classification of messages passing Layer 1. Crucially, classification and parsing in Layer 2 are completed within the same API call, incurring no extra cost.
    - **Design Motivation**: Filtering all messages directly with an LLM is cost-prohibitive; the dual-layer architecture significantly reduces API calls.

2.  **11K Bilingual Blood Donation Request Dataset**:
    - **Function**: Provides the first corpus of blood donation requests covering Bengali, English, and Transliterated Bengali.
    - **Mechanism**: 11K positive samples were collected from 15 public Telegram and Facebook groups. Negative samples were sourced from datasets like BengaliNMT and BengaliTLit, augmented with adversarial negative samples generated by DeepSeek-V3 containing keywords like "blood" or "urgent" to enhance robustness.
    - **Design Motivation**: Low-resource languages like Bengali lack specialized blood request datasets, and social media dialectal variations and slang require dedicated coverage.

3.  **LoRA Fine-tuned Llama-3.2-3B Parser**:
    - **Function**: Parses free-form text blood requests into structured JSON.
    - **Mechanism**: Llama-3.2-3B was fine-tuned using LoRA ($r=32, \alpha=16$), training only 0.81% of parameters on 7.9K text-JSON pairs. Output fields include `blood_group`, `bags_needed`, `hospital_name`, `contacts`, etc.
    - **Design Motivation**: Fine-tuning a small model outperforms big models like GPT-4o-mini in zero-shot settings while being 35x cheaper for inference.

### Loss & Training
Layer 1 uses asymmetric weighted binary cross-entropy:  
$$\mathcal{L} = -\alpha y \log P(y=1|\mathbf{z}) - (1-y)\log P(y=0|\mathbf{z})$$  
where $\alpha=12$. LoRA fine-tuning utilizes standard cross-entropy with 4-bit quantization and a learning rate of $2 \times 10^{-4}$.

## Key Experimental Results

### Main Results

| Method | Accuracy | Precision | Recall | F1 |
| :--- | :--- | :--- | :--- | :--- |
| DLF (Layer 1) | 0.99 | 0.99 | 0.99 | 0.99 |
| TFIDF+LogReg | 0.98 | 0.98 | 0.98 | 0.98 |
| DistilBERT | 0.98 | 0.98 | 0.98 | 0.98 |
| W2V+LogReg | 0.83 | 0.80 | 0.87 | 0.81 |

| Parsing Model | Zero-shot Accuracy | Notes |
| :--- | :--- | :--- |
| LoRA Llama-3.2-3B | 92% | Fine-tuned, zero-shot |
| Base Llama-3.2-3B | ~50% | Unmodified (+41.54% gain) |
| GPT-4o-mini (few-shot) | <92% | Few-shot still lags behind fine-tuned zero-shot |

### Ablation Study

| Configuration | Key Metric | Notes |
| :--- | :--- | :--- |
| Layer 1 Only | High recall, more false positives | Asymmetric weight ensures recall |
| Layer 1 + Layer 2 | 99% Accuracy | LLM filtering eliminates false positives |
| Without Adversarial Negatives | Lower Robustness | Adversarial samples strengthen classifier |

### Key Findings
- The dual-layer architecture effectively balances efficiency and precision; Layer 1 filters massive irrelevant data while Layer 2 eliminates false positives.
- The LoRA fine-tuned 3B model outperforms the few-shot performance of larger models like GPT-4o-mini in parsing, requiring 35x fewer input tokens.
- Adversarial negative samples (non-request texts containing keywords like "blood") significantly enhance the classifier's robustness.
- DLF significantly outperforms BERT-like models in inference speed.

## Highlights & Insights
- The **dual-layer "loose-in, tight-out" architecture** cleverly exploits the asymmetric costs of false negatives and false positives—Layer 1 allows more candidates through while Layer 2 refines them, with precise filtering and parsing consolidated into a single API call.
- Constructing the first blood request dataset for low-resource languages (Bengali + Transliterated) provides practical social value.
- The success of the LoRA fine-tuned small model over large model few-shot performance confirms the trend that "task-specific small models outperform general large models."

## Limitations & Future Work
- The dataset is primarily from social media groups in Bangladesh; generalization to other regions and languages remains unverified.
- Dependency on the GPT-4o-mini API introduces cost and privacy concerns.
- Only text messages are processed; blood request information in images is not considered.
- Parsing fields are predefined; new information types (e.g., insurance info) would require re-defining the schema.

## Related Work & Insights
- **vs Mathur et al. (2020)**: Their work only identifies blood requests on Twitter without structured parsing or support for Bengali.
- **vs CrisisBench**: A general benchmark for disaster information extraction that does not include specific tasks for blood requests.
- **vs Direct LLM Usage**: Not scalable; the DLF dual-layer architecture is a cost-optimization pattern applicable to other domains.
