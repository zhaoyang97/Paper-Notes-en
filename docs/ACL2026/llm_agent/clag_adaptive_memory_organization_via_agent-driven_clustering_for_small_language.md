# CLAG: Adaptive Memory Organization via Agent-Driven Clustering for Small Language Model Agents

**Conference**: ACL 2026  
**arXiv**: [2603.15421](https://arxiv.org/abs/2603.15421)  
**Code**: [https://github.com/dmis-lab/CLAG](https://github.com/dmis-lab/CLAG)  
**Area**: Model Compression  
**Keywords**: Small Language Models, Clustered Memory, Agent Memory Management, Local Evolution, Two-Stage Retrieval

## TL;DR
This paper proposes CLAG, a cluster-based Agent memory framework that organizes memories into semantically consistent clusters via SLM-driven routing, performs local evolutionary updates within clusters, and filters noise through two-stage retrieval, significantly outperforming global memory pool baselines on multiple QA datasets.

## Background & Motivation

**Background**: LLM Agents increasingly rely on external memory systems to support knowledge reuse and complex reasoning. Existing Agent memory systems have evolved from static RAG (append-only, global retrieval) to frameworks supporting active evolution (e.g., A-mem, MemoryOS, GAM) which can perform reflection, compression, and rewriting.

**Limitations of Prior Work**: These evolutionary memory systems still operate within a single global memory pool. As memory grows, global retrieval faces two coupled issues: (1) expanded search space increases the probability of retrieving semantically similar but task-irrelevant memories; (2) memory evolution mechanisms are exposed to topic-mixed neighborhoods, which may mislead updates and gradually degrade memory quality.

**Key Challenge**: These issues are particularly severe for Small Language Models (SLMs), as SLMs are extremely sensitive to irrelevant context. Cross-topic interference in global memory pools significantly impacts the response quality of SLMs.

**Goal**: Design a lightweight structured memory system for SLM Agents that maintains self-evolution capabilities while reducing cross-topic interference.

**Key Insight**: Drawing on the cognitive science principle that "new information should refine relevant schemas without disturbing irrelevant memory structures," this work treats clustering as an Agent-controlled active operation rather than a static preprocessing step.

**Core Idea**: Use SLM Agent-driven online clustering to organize memories into semantically consistent neighborhoods, restricting evolution and retrieval within local clusters to fundamentally reduce cross-topic interference.

## Method

### Overall Architecture
CLAG consists of three core components: (1) Agent Routing—allocating new memories to semantically consistent clusters; (2) Local Evolution—updating and consolidating memories within clusters; (3) Two-Stage Cluster-Aware Retrieval—filtering clusters before fine-grained retrieval within the selected clusters. All Agent decisions (routing/evolution/selection) are generated by the same SLM backbone via prompt calls for different roles.

### Key Designs

1. **Agent-Driven Memory Routing**:

    - **Function**: Assigns each new memory to the most semantically relevant cluster.
    - **Mechanism**: Operates in two stages. In the cold-start phase (processed memories < $n$), memories are buffered, and `InitializeClusters` establishes initial clusters once sufficient data is accumulated. Subsequently, for each new memory, Top-K candidate clusters are pre-filtered via vector distance, followed by SLM Agent review of candidate cluster semantic profiles for the final selection. If cosine similarity is below a threshold $\tau$, a new cluster is created. When a cluster exceeds the size threshold $\tau_{split}$, it is automatically bifurcated (K-Means) to prevent semantic drift.
    - **Design Motivation**: Pure vector distance may fail to distinguish subtle semantic differences; an SLM Agent can make more accurate judgments by reading cluster profiles. The adaptive splitting mechanism ensures clusters do not over-expand.

2. **Intra-Cluster Local Evolution**:

    - **Function**: Updates and integrates memories within semantically consistent neighborhoods to avoid cross-topic contamination.
    - **Mechanism**: After a new memory $m_{new}$ is routed to a cluster, Top-K most similar neighbors $\mathcal{M}_{local}$ are identified within that cluster. The SLM Agent first analyzes fine-grained relationships (causal, temporal, etc.) to generate links $L_{new}$, then determines for each neighbor whether an update is needed to reflect new information: $m_j^* \leftarrow \text{SLM}(m_{new} \| \mathcal{M}_{local} \setminus \{m_j\} \| m_j)$. Evolved memories replace the original ones, and the cluster profile is synchronized.
    - **Design Motivation**: Analogous to human cognition—new experiences primarily reshape the understanding of relevant concepts (i.e., the cluster they belong to) without affecting unrelated knowledge domains. Local evolution makes each cluster a self-optimizing module.

3. **Two-Stage Cluster-Aware Retrieval**:

    - **Function**: Narrows the search space and suppresses memory noise that is semantically similar but task-irrelevant.
    - **Mechanism**: Stage 1 (Agent Cluster Selection)—Query embeddings are calculated against cluster centroids to select Top-K candidates, and the SLM Agent evaluates the match between cluster profiles and the query, returning a variable-sized subset. Stage 2 (Intra-Cluster Retrieval)—Fine-grained vector retrieval is performed only among members of the selected clusters.
    - **Design Motivation**: In global retrieval, memories that are semantically similar but belong to different topics are the primary noise sources. The two-stage design uses cluster profiles for high-level semantic filtering, which is particularly beneficial for noise-sensitive SLMs.

### Loss & Training
No training is required; the framework operates at inference time. Decisions for routing, evolution, and retrieval are all completed through SLM prompt calls.

## Key Experimental Results

### Main Results (Three SLM backbones × Three datasets)

| Model | Method | LoCoMo F1 | HotpotQA F1 | BioASQ F1 |
|------|------|-----------|-------------|-----------|
| Qwen3-0.6B | RAG | 12.90 | 11.75 | 2.40 |
| Qwen3-0.6B | A-mem | 14.29 | 12.04 | 3.61 |
| Qwen3-0.6B | GAM | 16.05 | 7.81 | 3.40 |
| Qwen3-0.6B | **CLAG** | **20.99** | **15.50** | **22.01** |
| Llama3.2-1B | GAM | 22.63 | 13.85 | 6.52 |
| Llama3.2-1B | **CLAG** | **21.05** | **14.20** | **10.16** |

### Latency Comparison (Qwen3-0.6B)

| Method | Retrieval Latency (ms) | End-to-End Latency (ms) |
|------|-------------|---------------|
| RAG | 17.80 | 289.60 |
| GAM | 8303.41 | 17934.32 |
| CLAG | 142.43 | 514.14 |

### Key Findings
- CLAG shows the most significant improvement on BioASQ (Qwen3-0.6B: 2.40 $\rightarrow$ 22.01) because biomedical QA has high topic diversity, making cluster filtering most effective.
- In terms of latency, CLAG far outperforms GAM (514ms vs 17934ms) by avoiding global evolution operations.
- On the adversarial question subset of LoCoMo, CLAG's advantage is particularly prominent (50.34 vs GAM 41.25), indicating that clustering effectively suppresses interference memories.
- MemoryOS performs exceptionally poorly on small models (significantly below RAG baseline), suggesting its design is unsuitable for SLMs.

## Highlights & Insights
- **Clustering as an Agent Operation**: This work elevates clustering from static preprocessing to an Agent-controlled online operation, where cluster quality improves continuously with interaction. This "structure as intelligence" approach is generalizable to other long-term memory scenarios.
- **Local Evolution Avoids Global Contamination**: Restricting evolution within clusters makes each cluster a self-contained optimization unit. This is similar to modular neural network design—local updates do not affect the global state.
- **SLM-Friendly Design**: Two-stage retrieval significantly reduces the search space before SLM processing, effectively bypassing the vulnerability of small models to irrelevant context.

## Limitations & Future Work
- Cluster initialization requires accumulating a certain amount of memory (cold-start problem); benefits of clustering are unavailable in the initial phase.
- The quality ceiling of the SLM as a router is limited by model capability; routing may be inaccurate for topics with fuzzy semantic boundaries.
- Lack of experiments on large language models (LLMs); it is unconfirmed if clustering is equally effective for them.
- Automatic management of the number of clusters (split thresholds) requires domain-specific tuning.

## Related Work & Insights
- **vs A-mem**: A-mem evolves in a global pool with severe cross-topic interference. CLAG restricts evolution to clusters, improving Qwen3-0.6B F1 from 14.29 to 20.99.
- **vs GAM**: Global evolution in GAM leads to extremely high latency (17934ms). CLAG’s intra-cluster local evolution takes only 514ms, which is 35x faster.
- **vs MemoryOS**: Performance of MemoryOS collapses on SLMs (below RAG baseline), indicating its design assumes stronger model capabilities. CLAG is optimized specifically for SLMs.
