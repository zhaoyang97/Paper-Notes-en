# HIVE: Query, Hypothesize, Verify — An LLM Framework for Multimodal Reasoning-Intensive Retrieval

**Conference**: CVPR 2026
**arXiv**: [2604.07220](https://arxiv.org/abs/2604.07220)
**Code**: [https://github.com/mm-bright/multimodal-reasoning-retrieval](https://github.com/mm-bright/multimodal-reasoning-retrieval)
**Area**: Multimodal VLM
**Keywords**: Multimodal Retrieval, Visual Reasoning, Query Reformulation, LLM Reranking, Hypothesis-Driven Retrieval

## TL;DR

HIVE is a plug-and-play multimodal retrieval framework that improves nDCG@10 from 27.6 (best multimodal model) to 41.7 (+14.1 absolute points) on reasoning-intensive multimodal retrieval through four stages — initial retrieval → LLM-driven compensatory query synthesis (explicitly expressing visual reasoning gaps) → secondary retrieval → LLM verification reranking — without any additional training.

## Background & Motivation

1. **Background**: Dense retrieval (bi-encoder) is the dominant paradigm for large-scale information retrieval, achieving strong performance on factual benchmarks such as BEIR (nDCG@10 of 59.0). However, performance drops sharply to 18.3 on reasoning-intensive queries (e.g., the BRIGHT benchmark). Recent work such as DiVeR mitigates this through reasoning-aware fine-tuning, iterative query expansion, and hybrid reranking, but is limited to the text-only setting.

2. **Limitations of Prior Work**: Real-world queries increasingly contain images (error screenshots, scientific diagrams, circuit schematics, etc.). The MM-BRIGHT benchmark shows that the SOTA multimodal retrieval model achieves only 27.6 nDCG@10 — even worse than text-only retrievers (32.2). Incorporating visual information actually hurts performance. The root cause is that embedding models perform superficial semantic matching and cannot reason about what image content implies for document relevance.

3. **Key Challenge**: Standard multimodal retrievers compute relevance as $\text{score}(q,d) = \cos(\phi(q_t, q_v), \psi(d))$, but this formulation has no mechanism to reason about "what the query image implies." For example, given a circuit diagram paired with the text query "LED not lighting up," the retrieval system must understand circuit topology to find relevant documents — a capability beyond embedding similarity.

4. **Goal**: (a) How can visual reasoning be injected into retrieval without retraining models? (b) How can the gap between embedding matching and reasoning-intensive retrieval be bridged?

5. **Key Insight**: After observing initial retrieval results, an LLM can precisely identify which visual and logical dimensions are needed by the query but not covered by the retriever, enabling the generation of targeted compensatory queries. This mirrors how a human expert reformulates a query upon receiving unsatisfactory search results.

6. **Core Idea**: Use the LLM as a "visual reasoning mediator" that generates compensatory queries between two retrieval rounds to explicitly capture visual-logical associations that the retriever cannot, followed by verification reranking to filter noise.

## Method

### Overall Architecture

HIVE is a four-stage plug-and-play framework that wraps any base retriever. The input is a multimodal query $(q_t, q_v)$ (text + image) against a text-only document corpus. Stage 1: initial retrieval obtains a small probe set; Stage 2: the LLM analyzes the probe results and image description to generate compensatory queries; Stage 3: secondary retrieval with a larger search window using the compensatory queries; Stage 4: the LLM verifies and reranks the union of both retrieval rounds. No training is required; the entire pipeline runs at inference time.

### Key Designs

1. **Compensatory Query Synthesis**:

    - Function: Generates targeted query expansions that address visual reasoning gaps.
    - Mechanism: The LLM is provided with three inputs — the original text query $q_t$, an image description $\delta(q_v)$ (generated by GPT-4o), and the top-$k_1$ documents $\mathcal{D}^{(1)}$ from the initial retrieval. The LLM is instructed to: (1) identify content in the image beyond what the text query conveys; (2) assess which query intents are uncovered or only partially covered by the probe documents; (3) generate a concise compensatory query $\hat{q}$. For example, if the query image is a Python stack trace and the retrieved documents are generic debugging articles, the LLM generates a compensatory query containing the specific error type and module names visible in the image. Formally: $\hat{q} = \mathcal{L}(\text{HypothesisPrompt}(q_t, \delta(q_v), \{d_{r_i}\}_{i=1}^{k_1}))$
    - Design Motivation: Unlike standard query expansion (which rewrites the text query in isolation), HIVE's compensatory queries are conditioned on both (i) the visual content of the query image and (ii) the actual content of the initial retrieval results. This dual conditioning makes the expansion targeted — specifically compensating for missing coverage rather than generic reformulation.

2. **Secondary Retrieval**:

    - Function: Uses the compensatory query to search a broader range for documents missed by the initial retrieval.
    - Mechanism: A second retrieval pass is conducted with compensatory query $\hat{q}$, using $k_2=50 \gg k_1=5$, since $\hat{q}$ targets a different semantic subspace from the original query and thus requires a larger search window. The final candidate pool is the deduplicated union of both retrieval rounds $\mathcal{U} = \mathcal{D}^{(1)} \cup \mathcal{D}^{(2)}$, with $|\mathcal{U}| \leq k_1 + k_2$.
    - Design Motivation: The larger $k_2$ is intentional — compensatory queries cover semantic space not touched by the original query, requiring broader search to surface relevant documents missed in the initial pass.

3. **Verification & Reranking**:

    - Function: Performs final semantic verification and ranking over the candidate union.
    - Mechanism: The LLM acts as a "verification agent" — given the full visual-textual query context and all candidate documents, it reasons step by step about which documents most effectively address the user's multimodal intent, outputting a ranked JSON list of document IDs. Scoring: the $k_f$ documents selected by the LLM receive scores of $S_{\max} - \text{rank}_i$ ($S_{\max}=1000$); remaining documents receive $S_{\text{base}} - \text{offset}_i$ ($S_{\text{base}}=500$) in original retrieval order, ensuring full coverage.
    - Design Motivation: Stages 2–3 expand candidate coverage but introduce noise; Stage 4 filters noise to ensure precision in the final ranking. Ablations show synergy: Stage 2–3 alone (expansion without verification) yields 38.1; Stage 4 alone (verification without expansion) yields 37.2; the full pipeline achieves 41.7.

### HIVE-Retriever Base Retriever

A standalone reasoning-enhanced embedding model based on Qwen3-Embedding-4B, fine-tuned on synthetic hard-negative contrastive data. Embeddings are derived from the last-layer hidden state of the EOS token, with cosine similarity for retrieval. Multimodal queries are formed by concatenating the GPT-4o image description $\delta(q_v)$ with the text query $q_t$.

## Key Experimental Results

### Main Results

nDCG@10 on MM-BRIGHT (2,803 queries, 29 technical domains):

| Method | Type | nDCG@10 |
|--------|------|---------|
| CLIP | Multimodal | 10.4 |
| Nomic-Vision | Multimodal | 27.6 |
| DiVeR | Text-only | 32.2 |
| HIVE-Retriever (base) | Text-augmented | 33.2 |
| **HIVE (Full)** | **Framework** | **41.7** |

HIVE achieves the best performance in 28 out of 29 domains. Strongest domains: Gaming 68.2, Law 64.6, Ubuntu 53.6.

### Ablation Study

| Configuration | nDCG@10 | Note |
|--------------|---------|------|
| HIVE-Retriever (no framework) | 33.2 | Baseline |
| + Stage 2 only (compensatory query) | 35.3 (+2.1) | Query expansion helps |
| + Stage 4 only (verification reranking) | 37.2 (+4.0) | Verification contributes more |
| + Stage 2+3 (expansion without verification) | 38.1 (+4.9) | Expansion coverage |
| **Full HIVE (1–4)** | **41.7 (+8.5)** | Expansion + verification synergy |

Plug-and-play validation (different base retrievers):

| Base Retriever | Base | +HIVE | Δ |
|---------------|------|-------|---|
| CLIP | 10.4 | 20.5 | +10.1 |
| Nomic-Vision | 27.6 | 34.1 | +6.5 |
| HIVE-Retriever | 33.2 | 41.7 | +8.5 |

### Key Findings

- **Consistent gains across all base retrievers**: HIVE yields significant improvements regardless of retriever strength — from weak (CLIP +10.1) to strong (HIVE-Retriever +8.5) — with weaker retrievers benefiting more due to larger semantic gaps being compensated.
- **Clear synergy between compensatory query synthesis and verification reranking**: Each component alone contributes +2.1 and +4.0 respectively, but their combination reaches +8.5, exceeding simple addition.
- **Visual information density determines gain magnitude**: HIVE achieves the largest gains in domains where images carry dense domain-specific information (Academic +22.8, Economics +28.1, Sustainability +24.7), and the smallest gains in abstract domains (Quantum Computing, Cryptography).
- **Analysis of the sole failure case**: In the Salesforce domain, GME-7B (47.3) outperforms HIVE (44.9) because the structured layout of CRM screenshots is directly captured by contrastively trained GME-7B, leaving limited marginal benefit for compensatory queries.
- **Lightweight configurations remain effective**: Even with the minimal setting $k_1=3, k_2=30$, performance still improves by 5 points over the baseline (38.2 vs. 33.2).

## Highlights & Insights

- The **two-round retrieval paradigm of "diagnose failure → targeted compensation"** is notably elegant: the first-round results serve not only as answer candidates but as diagnostic signals indicating "where retrieval fell short." This idea of generating improvement directions from initial retrieval failures is transferable to many iterative refinement scenarios.
- **Using LLMs as reasoning engines within the retrieval pipeline** represents an important trend: LLMs do not replace embedding-based retrieval but layer reasoning on top of it, with the two being complementary. This design pattern (cheap fast retrieval + expensive LLM reasoning) has broad applicability.
- **Completely training-free inference-time augmentation** drastically lowers the barrier to adoption: any retrieval system can immediately integrate HIVE without model retraining.
- Domain-level analysis precisely delineates HIVE's capability boundaries: when images carry minimal additional information (e.g., abstract quantum computing diagrams), compensatory queries provide limited benefit.

## Limitations & Future Work

- Reliance on GPT-4o for image description, compensatory query synthesis, and verification reranking results in three LLM calls per query, incurring high inference costs.
- The image description $\delta(q_v)$ is a potential bottleneck for the entire pipeline — misunderstanding of image content by GPT-4o will propagate errors into the compensatory queries.
- Only the multimodal-to-text retrieval scenario is evaluated; multimodal-to-multimodal retrieval is not addressed.
- The scoring heuristic for candidate reranking ($S_{\max}=1000, S_{\text{base}}=500$) is relatively hand-crafted and may not be globally optimal.
- No comparison is made against end-to-end trained reasoning-enhanced retrievers (e.g., those learning compensatory query generation from retrieval feedback via RL).

## Related Work & Insights

- **vs. DiVeR**: DiVeR is a text-only reasoning-enhanced retriever (document preprocessing + feedback-driven query expansion + hybrid reranking) achieving SOTA on BRIGHT. HIVE-Retriever alone already surpasses DiVeR (33.2 vs. 32.2), and the full framework further extends the gap to 41.7.
- **vs. Nomic-Vision**: The current best multimodal embedding retriever (27.6), whose embedding similarity cannot reason about image implications. Wrapping it with the HIVE framework improves performance to 34.1.
- **vs. ColPali/VisRAG**: These methods address visual document retrieval (where documents are also images), whereas HIVE targets multimodal query → text document retrieval — complementary rather than competing settings.

## Rating

- Novelty: ⭐⭐⭐⭐ The paradigm of "diagnosing gaps from initial retrieval failures and generating compensatory queries" is novel and effective, though the four-stage pipeline is methodologically straightforward.
- Experimental Thoroughness: ⭐⭐⭐⭐⭐ Comprehensive evaluation across 29 domains, plug-and-play validation over 5 base retrievers, component ablations, and hyperparameter sensitivity analysis — very thorough.
- Writing Quality: ⭐⭐⭐⭐ Problem formulation is clear, experimental analysis is in-depth, and domain-level analysis provides valuable insights.
- Value: ⭐⭐⭐⭐⭐ The training-free plug-and-play design has high practical utility, and a 14.1-point absolute improvement is highly significant in the retrieval community.
